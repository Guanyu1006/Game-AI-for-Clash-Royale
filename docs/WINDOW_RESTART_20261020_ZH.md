# 两次窗口中断的核查与恢复

用户确认中断的是整个 VS Code／Codespaces 窗口。当前观察到远程容器／进程重建，尚不能认定宿主重启，也不能确定是资源耗尽、客户端崩溃、平台停止或某条开发命令直接造成。

## 已有证据

- 远程开发日志分别有北京时间 2026 年 10 月 20 日 19:47、20:24 的启动会话；本次容器 PID1 的启动时间为 20:23:56。
- 原来运行的 QEMU、项目 ADB 和未完成身份采集进程均已不存在，磁盘上的源码、APK、更新包、已安装游戏磁盘和日志仍存在。
- 重启后核查磁盘约有 14 GiB 空闲、系统可用内存约 4.7 GiB，当前 cgroup 的 `oom/oom_kill` 为 0。这些计数无法证明重启前没有 OOM；宿主内核历史日志无读取权限。
- 扩展启动日志有工作区 `vscode.lock` 已存在及 JSON 读取错误。它们出现在恢复阶段，不能据此认定是窗口崩溃根因。没有删除用户扩展状态、会话或凭据。
- 前期确实修复过 QEMU 停机脚本路径错误导致的重复启动尝试与端口冲突。该错误影响项目虚拟机管理；尚无证据把它与两次整个窗口重启直接关联。没有执行 Codespace 停止、重建或宿主重启命令。

原始核查的安全摘要见 [重启核查回执](../outputs/native_loop_20261020/window-restart-audit-001/report.json)。未复制包含账户信息的扩展原始日志。

## 已做的降低负载措施

1. 新增 [.vscode/settings.json](../.vscode/settings.json)，排除虚拟环境、缓存、大型生成数据和原生二进制目录的常规监听／搜索。源码仍正常开发，结果仍可直接打开，未删除文件，也未改变 Windows 解释器。
2. 只恢复一台 1536 MiB、1 vCPU 的软件 VM，使用 `nice -n 10` 降低宿主调度优先级；资源核验、模拟和训练串行执行。
3. 保留原已安装磁盘，通过新私有副本恢复，未重复下载资源或重建 APK；新入口使用 writeback，并保存独立 attempt、PID 启动时间、QMP 和日志。
4. [轻量采样](../outputs/native_loop_20261020/resource-watch-recovery-001/process.json)每 5 秒记录可用内存、负载、压力与 OOM 计数，最多 15 分钟；不自动修改游戏或结束进程。若再次中断，可以检查最后样本，而不凭感觉归因。

这属于减小风险和增加证据，不能宣称已经证明窗口崩溃被修好。

## 21:40 再次恢复检查

收到“继续”后，旧 VM、ADB 和对局进程再次不存在；新容器 PID1 的启动时间约为北京时间 21:32:35。第二段资源采样的最后时间是 20:57:47，最后可用内存约 2.33 GiB，采样期间最低约 2.30 GiB，`oom/oom_kill` 仍为 0。中断与重新连接之间没有连续记录，不能据此排除平台停止或旧宿主故障，也不能把“继续”消息本身认定为重启原因。

这次原生对局已真实建局和推进：保存了 254 条完整转移、15 次我方出牌消耗，原生状态最后到 2631 tick；最后一个完整转移到 2630 tick。尚未自然终局，不计为完整对局。现场见[第二次恢复核查](../outputs/native_loop_20261020/window-restart-audit-002/report.json)和[对局中断记录](../outputs/native_loop_20261020/native-smoke-001/interruption.json)。

磁盘中已安装游戏与资源仍保留。恢复工具增加显式复用已停止实例的私有磁盘选项，避免再复制数 GB 磁盘；每次新建日志和进程记录。进程重建后需重新采集身份，不恢复旧 RPC 连接或猜测未收到回执的动作是否执行。

## 还需核对的外部条件

GitHub 的[闲置规则](https://docs.github.com/en/codespaces/setting-your-user-preferences/setting-your-timeout-period-for-github-codespaces)默认 30 分钟，用户输入与终端活动可重置计时。[停止与启动说明](https://docs.github.com/en/codespaces/developing-in-a-codespace/stopping-and-starting-a-codespace)明确停止会结束进程并保留已保存文件。当前没有取得该 Codespace 的停止事件或实际超时配置，时间接近仅是排查线索；没有擅自修改账户超时或计费设置。

若再次出现问题，优先保留当时的完整错误文字、时间和“断线／需要 Start／窗口关闭”等具体表现，再核对 Codespaces 停止事件、本地 VS Code 日志及宿主内存记录。当前证据不能区分这些外部触发因素。

## 本次恢复边界

旧身份采集 `identity-check-002` 被中断，没有生成可用于新进程的身份回执，另存 `interruption.json`。新 VM 必须重新确认 Android 启动、游戏内容就绪及当前进程身份；不能沿用旧 PID、假定上次动作已成功，或把 Android 启动成功当作原生对局成功。

继续原生配置、启动和小规模闭环见 [原生操作指南](NATIVE_LOOP_ZH.md) 与[软件 Android 指南](SOFTWARE_ANDROID_TCG_ZH.md)。
