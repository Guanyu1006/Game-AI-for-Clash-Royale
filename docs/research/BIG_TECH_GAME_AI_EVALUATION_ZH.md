# 大厂游戏 AI 论文的评价方法与皇室战争迁移设计

调研日期：2026年10月18日。本文补充[Benchmark设计草案](BENCHMARK_DESIGN_ZH.md)，重点分析OpenAI Five、VPT、Google DeepMind的Dreamer与SIMA、NVIDIA合作团队的Minecraft研究，并连接微软、腾讯和索尼的代表性评价方法。

最适合本项目的组合是：采用OpenAI Five的固定参考对手与挑战测试，采用VPT的长任务里程碑诊断，采用Dreamer的分阶段消融与真实环境验证，再采用SIMA的分技能、分泛化层次和多种成功判定。以下“迁移设计”均为本项目建议，不是论文已在皇室战争上验证的结论。所有外部成绩为作者报告，本次未复现训练。

## OpenAI Five 如何分层证明对战强度

[Dota 2 with Large Scale Deep Reinforcement Learning](https://cdn.openai.com/dota-2.pdf)的评价同时包含：83个参考代理组成的TrueSkill池，每个被测版本累计750局；对OG的2比0；公众Arena中对3,193支队伍的7,257局，作者报告胜率99.4%。附录J披露参考池和匹配规则。它使用结构化接口并限制英雄与部分操作，弃赛也按胜利计入。

这些实验分别回答不同问题：参考池衡量训练进展；职业队比赛验证是否能应对顶级对手；广泛挑战测试更多战术与针对性。少量职业比赛的传播效果不能替代对总体稳定性的评价，公众挑战的自愿参与人群也不能自动代表全体玩家。

迁移设计：

1. 为训练进度维护固定的随机、规则、学习和搜索锚点，保存其hash、版本和行为配置。可以逐步增加新锚点，但历史曲线要在共同参考池中重评，或明确标注评分体系改变。
2. 训练进度池属于开发信号，另保留密封对手与场景做最终测试。反复根据参考池成绩改方法后，参考池不再是独立泛化证据。
3. 真人测试可以从分层招募的小规模受控实验开始。另让熟悉AI弱点的玩家或攻击代理尝试针对，以测查固定策略漏洞。
4. 定义相同的观察、动作与实际反应预算；公开结构化输入的结果和像素闭环结果分轨道。
5. 完整披露弃赛、崩溃、超时与重跑规则。对原生环境不稳定导致的缺失，不伪装为游戏平局。

TrueSkill或Elo适合汇总同一规则下对参考池的相对强度。皇室战争卡组克制更容易混入结果，因此主表仍保留按卡组对阵分层的得分和交叉矩阵，不将内部评分直接换算成官方杯数。

论文可借鉴的图：横轴真实交互量或训练计算量，纵轴共同对手池得分，另标真人验证点。若引擎、动作空间或卡组范围改变，把这些变化与曲线一起显示。

## VPT 如何评价从视频学会长任务

[Video PreTraining](https://cdn.openai.com/vpt/Paper.pdf)采用原生鼠标键盘接口。它分别测试动作伪标签、离线损失、游戏内行为、预训练后的BC与RL微调、数据规模。图4的基础模型统计来自2,500个60分钟episode；钻石镐挑战采用10分钟episode，最终方案成功率为2.5%。两种episode协议不能混用。

它适合本项目的核心经验，是把漫长任务拆成可以实际验证的进展链，再检验预训练改善了哪些环节。里程碑负责定位瓶颈，终点成功率保留为最终目标。

迁移设计可以定义如下对战进展链：

| 层次 | 皇室战争中可测量的内容 | 注意事项 |
| --- | --- | --- |
| 输入与感知 | 对威胁单位、本人资源和可用牌的识别 | 真实图像测试与结构观察测试分开 |
| 动作提议 | 时机、卡牌、位置是否落在合理范围 | 允许多个有效方案 |
| 实际执行 | 命令是否唯一确认消费 | 请求被接受与实际生效分开 |
| 局部效果 | 是否在固定窗口完成防守，塔伤与消耗如何 | 按事先定义的威胁场景计分 |
| 后续转换 | 防守后能否保持资源并形成反击 | 冻结对手响应与后续窗口 |
| 完整目标 | 最终整局得分 | 各阶段成绩不能代替整局结果 |

同时报告每层条件成功率，以及从最初场景开始的联合成功率。例如仅在成功下牌的动作中计算防守成功率，会掩盖执行模块丢失大量动作的问题。

若主张“利用回放或视频提高学习效率”，至少比较：少量可信动作数据直接BC；相同可信数据加弱标签预训练再BC；预训练后再RL；相同环境交互预算的从零RL。记录独立对局、时长、确认出牌、数据清洗和标签成本，不能只对比训练行数。

伪标签器离线利用未来画面重建动作，在方法上可以成立；部署actor只能使用当前及过去信息。未来信息的使用权限按模块区分，不能从标签生成悄悄扩散到actor特征。

## DreamerV3 如何支撑算法通用性的主张

[DreamerV3论文](https://arxiv.org/pdf/2301.04104)及[Nature 2025版本](https://www.nature.com/articles/s41586-025-08744-2)在多类任务中采用固定核心超参数。Minecraft方法部分明确：10个训练seed、100M环境步；输入包含图像和背包等结构量，接口提供抽象合成动作，奖励覆盖12个技术树里程碑。它与VPT的纯原生控制协议不同。

这里需要区分两种研究主张：同一种学习算法在多个任务中分别训练都有效；同一份模型权重可以直接处理未见任务。DreamerV3的跨域算法评价不能被改写成后一种零样本通用代理主张。

迁移设计：

- 若研究训练方法的稳健性，冻结核心超参数，在多个卡组或任务上分别训练，公开所有调参和计算预算。
- 若研究多卡组统一策略，必须测试同一checkpoint，明确训练见过的牌与组合。
- 若研究卡组泛化，保留未参与训练及模型选择的八卡组合，进一步区分是否包含未见单卡。
- 若研究世界模型，需要相同环境交互量下的学习曲线，也需要墙钟和模型调用成本；模型内生成的经验不等于免费真实经验。

可以把Minecraft技术树的思想迁移成对战能力覆盖，而不能照搬它的任务奖励。皇室战争中一个局部防守的收益取决于后续对手响应，局部奖励尤其容易诱导片面行为。

曲线阴影究竟是标准差、标准误还是置信区间，必须逐图注明。大厂论文某项采用多少seed并不是本项目自动充分的样本量标准，应按训练变动和目标提升幅度决定。

## Dreamer 4 如何检验世界模型的实际价值

[Training Agents Inside of Scalable World Models](https://arxiv.org/html/2509.24527v1)第4.1节比较BC、世界模型表征加BC、想象RL等阶段。最终在真实Minecraft的随机世界、空背包、60分钟任务中测试1,000个episode，报告各里程碑成功率和耗时；钻石成功率0.7%。评价使用预设任务提示序列，需要与无分阶段指导的自主控制区分。

对本项目最有价值的是构造“机制链”，让每个新增模块都有直接对照：

| 阶段 | 保留条件 | 新增变化 | 需要看什么 |
| --- | --- | --- | --- |
| BC | 固定真实数据与基础输入 | 基础策略 | 整局与战术表现 |
| 表征加BC | 相同真实数据、相同动作权限 | 世界模型预训练表征 | 表征是否对行动有益 |
| 想象训练 | 相同真实交互数据 | 模型内策略优化 | 真实游戏得分是否进一步提高 |
| 简单模型对照 | 相同规划/训练预算 | 规则外推或简单动力学 | 复杂模型是否必要 |

世界模型自身还应检查：给定动作后事件能否发生、对象能否持续、资源守恒是否合理、部署与伤害次序是否正确。像素质量与动作条件下的机制正确性是不同指标。

如果我们为模型提供“防守完成后切换反击”等外部阶段提示，其他代理也应得到相同提示，并另测自主选择阶段。否则会把外部规划器的贡献计入策略自身。

0.7%的结果说明论文可以围绕一个严格定义、困难且以前没有实现的设置建立贡献；它不意味着任何低成功率都有论文价值。需要强基线、明确增量、稳定中间进展和可信的终点证据，才能解释稀有成功。

## SIMA 2 如何评价能力覆盖与泛化

[SIMA 2技术报告](https://arxiv.org/html/2512.04797v1)第3.4节采用环境真值、画面程序判定、人工评审三类成功函数，人工视频评价每条5个独立评分。它区分已训练环境中的留出任务与完全留出环境，并在后者测试ASKA和MineDojo。真人基线也区分熟悉游戏的玩家与首次接触新游戏的玩家。

本项目可以据此采用三种裁判：

1. 能取得可信原生真值时，胜负、费用消费、HP变化与事件由程序判定。
2. 真实客户端只能取画面时，用明确的OCR/视觉规则评价，同时在独立标注样本上测量裁判误差。
3. 战术意图、解释或其他难以形式化的问题，使用盲评、固定rubric及多个评审。把评审意见与程序事实分开。

裁判允许读取底层状态，不表示actor也能读取。可以用真实敌方圣水检验belief误差，同时保持actor只接收公开历史。评价信息与决策信息之间的隔离要能审计。

对泛化，至少区分同类任务的新实例、未见卡组组合、未见对手、二者联合变化。若以后增加其他游戏，才讨论跨游戏迁移；同游戏换卡组的结果不足以支持同等层次的主张。

顺序任务也值得迁移：从一次防守开始，连续执行防守、反击和终盘决策，只有链条全部成功才算该复合任务成功，另报每一步的条件成功率。失败后reset再做下一步属于分解测试，不能记成完整链条成功。

真人比较应对齐起始状态、时间预算、练习机会与游戏经验。若测试一个新卡组的即时适应，使用熟悉该卡组的玩家作参照与使用首次接触者作参照，回答的是不同问题。

## MineDojo 如何定义可扩展任务套件

[MineDojo论文](https://arxiv.org/abs/2206.08853)和[官方任务说明](https://docs.minedojo.org/sections/core_api/sim.html)区分可由状态自动判定的Programmatic任务与缺乏简单判据的Creative任务；前者包括生存、资源、技术树和战斗。任务变化由初始条件、目标和成功函数等明确规定，创造性任务还涉及学习评价与人工一致性核查。

我们可以把一题战术写成如下任务对象：

```text
任务类别：建筑拉扯
环境：冻结引擎与资源版本
初始条件：可验证的重演前缀、双方卡组、起手、公开历史
actor权限：指定观察轨道
目标：固定时间窗口内减少塔伤
成功函数：目标变化、塔伤和消耗满足预声明条件
变化因素：进攻方向、距离、卡序、资源、执行延迟
失败类型：策略失误、执行失败、环境异常、不可判定
```

这样的任务生成器比手工收集几个演示更容易扩展，但生成数量不等于能力覆盖。应先覆盖机制与决策类型，再为每一类生成新实例，并核查它们是否真的需要不同决策。

皇室战争终局有明确胜负，主结论应优先用可验证结果。学习裁判可以辅助分析“打法是否合理”，不宜让训练奖励模型独自决定同一代理的最终研究成绩。

## Voyager 如何评价技能积累与迁移

[Voyager论文第3节](https://arxiv.org/html/2305.16291v2)评价物品多样性、技术树、地图覆盖和新世界任务迁移，并消融课程、技能库与反馈。技术树表以3次运行报告成功分母和提示迭代数。它使用Mineflayer高层代码API，作者明确不与像素输入、低层操作的方法做直接同条件比较。

迁移设计：如果未来把防守、拉扯、法术和反击做成可调用技能库，就需要检验：

- 技能库是否提高新战术组合的成功率，而不只是增加同题重复率。
- 换卡组、清空临时状态后，历史技能是否仍有效。
- 相同LLM、相同API、相同token与时间预算下，有无技能库差多少。
- 调用高层技能相较逐次出牌，获得多少控制抽象优势。

可比较的统计量包括达到指定成功率所需的真实训练局数、解决的独立任务族数量、复合任务成功率和调用成本。提示迭代数、环境步数、模拟秒数与墙钟时间分开，不能把一种效率直接换成另一种。

技能库若在正式测试期间更新，应明确这是在线适应实验，并规定可用反馈与预算；静态策略泛化实验中则冻结技能库，避免把测试经验泄漏到后续题目。

## 微软 Malmo 的平台贡献

[Malmo平台论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/07/johnson-malmo-platform-camera-ready.pdf)主要贡献是把Minecraft开放为支持任务设计和代理交互的研究平台，而非宣称一个强代理已经解决Minecraft。它为导航、生存、构建与多代理等任务提供实验接口。

对本项目的启发是把平台贡献与算法贡献分清：即使策略还不强，一个有明确观察权限、任务定义、运行时钟、可靠重置、日志和冻结评价协议的平台也可以形成研究价值。它仍需要与已有平台做功能及成本比较，展示研究者真正能够完成的实验。

## 另外三条大厂路线

### 腾讯王者荣耀

[Towards Playing Full MOBA Games with Deep Reinforcement Learning，NeurIPS 2020](https://proceedings.neurips.cc/paper_files/paper/2020/file/06d5ae105ea1bea4d800bc96491876e9-Paper.pdf)报告职业队与大规模高水平玩家测试，并研究扩大英雄池时的学习问题。其评价还包含共同资源下的训练比较和算法组件分析。

迁移到皇室战争，最直接的问题是扩大卡牌与卡组组合后，方法能否继续有效。先固定卡组测控制，再扩大组合测容量和泛化；卡组选择本身若参与优化，作为上层任务独立评价，不能与固定卡组控制混成同一个贡献。

### 微软 Suphx 麻将

[Suphx，2020](https://arxiv.org/pdf/2003.13590)在同一平台和规则中比较稳定段位及行为统计，并讨论峰值段位不能充分表达真实强度；论文使用对局日志的重复抽样分析变动。它也涉及特权信息引导和部署阶段的不完全信息决策。

对应本项目，最高杯数或某次最佳连胜仅作背景；主评价采用固定样本范围内的得分分布和不确定性。特权teacher、critic或标签来源，必须与部署actor区分。

### 索尼 GT Sophy 赛车

[GT Sophy，Nature 2022](https://sam.barrettnexus.com/publications/papers/nature22.pdf)区分计时赛和竞争赛，并额外研究感知延迟：在指定计时赛设置中，以100、200和250毫秒延迟重新训练代理。该实验检验速度优势与控制能力的关系。

皇室战争也应对反应延迟作干预。分别测试冻结模型增加延迟的退化，以及允许在延迟条件下重新训练后的恢复；这两者回答部署鲁棒性与可适应性，不能混算。把观察到实际出牌消费的延迟作为关键变量，而不是只测forward耗时。

## 哪些大厂经验需要改进后再采用

知名论文不是统一实验规范，各篇资源、年份和研究主张不同。建议主动补上：

| 常见做法或限制 | 本项目的处理 |
| --- | --- |
| 单个巨大训练run | 核心方法尽量增加独立训练运行，保留全部结果 |
| 少量真人展示 | 受控分层真人实验与更广的对手池并用 |
| 公众挑战胜率 | 披露参与人群、弃赛和重复挑战，不推断全体玩家 |
| 仅报告首次完成困难任务 | 补任务成功分母、重复运行、里程碑与失败原因 |
| 不同API或辅助脚本 | 建观察与动作轨道，或给所有方法同等辅助 |
| 仅展示视频或模型评分 | 主指标使用独立的实际游戏结果与可验证事件 |
| 部分实验seed很少 | 将其视为证据限制，不把名气当作充分性依据 |

## 建议本项目新增的四个研究问题

| 研究问题 | 借鉴来源 | 实验 |
| --- | --- | --- |
| 在固定对手池与挑战池里是否稳定提高整局表现 | OpenAI Five、腾讯MOBA | 多训练运行、共同配置、换边、分组得分 |
| 视频或回放学习改善了对战链的哪一环 | VPT | 相同数据预算下的预训练/BC/RL分阶段比较 |
| 世界模型改善的是表征还是策略优化 | DreamerV3/4 | BC、WM加BC、WM加想象训练、简单模型对照 |
| 能力能否迁移到新组合和更长任务链 | SIMA、Voyager、MineDojo | 留出卡组/对手、战术复合任务、技能库冻结测试 |

建议优先产出六组图表：固定对手池学习曲线；密封对手交叉矩阵；对战进展链的联合与条件成功率；核心模块消融；不同泛化轴的表现；延迟与得分的关系。仅在世界模型成为主要贡献时，再增加多步预测、动作排序与真实闭环收益之间的比较。
