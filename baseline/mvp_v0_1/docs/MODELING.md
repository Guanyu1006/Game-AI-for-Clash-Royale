# 问题建模

## 任务与信息边界

真实任务可视为部分可观察的双人实时随机博弈。双方同时决定何时使用哪张卡、放在哪个位置；单位后续运动和攻击由游戏引擎执行。观察只包括画面中可见的信息：我方手牌、圣水、时间、单位、塔血和可确认的出牌事件。对手当前手牌、精确圣水、完整卡组及未检测到的事件属于隐藏变量。

用 `s_t` 表示完整状态，`o_t = O(s_t) + 感知误差` 表示观测，`a_t = (slot, x, y)` 或 `WAIT` 表示动作。真实控制还需要下牌时间/等待时长；MVP 每隔固定周期重新决策，默认模拟周期 2 秒，真实轮询默认 1 秒。

长期目标应是最大化对不同对手的获胜概率，同时约束非法动作率与决策延迟。单次防守少受伤、赚圣水和反打价值只是代理目标，不能自动等同于最终胜利。

## MVP 状态表示

竞技场归一到宽 18、高 32；我方在下半场，河流 `y=16`。从另一方观察时旋转 180 度并交换 team。每次观测包含时间、我方 4 张手牌和下一张牌（若可见）、圣水、6 塔状态、单位集合、观测置信度、事件列表。

实体使用 `(id, card, team, x, y, hp, cooldown, ready_at, expires_at)`。模拟器能提供这些理想化字段；真实视觉暂时只可靠提供类别、阵营和位置，单位 HP 使用研究参数的满血估计，攻击冷却和出场时间尚未识别。这是必须消除的输入分布差异。

没有把对手真实手牌或真实圣水写入策略观测。搜索重建的隐藏状态来自先验和可见历史。

## 对手信念近似

可靠出牌事件下，圣水区间 `[l,h]` 先按模型中的恢复速度推进，再扣已确认卡费并截到合法范围。重复事件 ID 只处理一次。区间矛盾会计数并放宽估计，避免以不可能的推断继续决策。

基础四卡轮转约束：卡牌使用后，至少再使用四张其他卡才可能回到手中。只对可靠 `play` 事件应用这一约束。截图里新出现一个单位不等于刚下了一张牌，所以 `seen` 只更新已见卡牌集合。由于画面可能漏掉单位和法术，当前 screen 模式保守保持 `[0,10]`，没有声称已实现精确的视觉圣水追踪。

中途接入时从当前观测时间开始推断，不假定之前没有花费。模拟器从开局接入可使用 `[5,5]` 初始值。当前候选敌方卡牌由已见类别及默认八卡先验组成；这不是归一化的贝叶斯后验，也不是精确的对手手牌重建。英雄、镜像、进化周期等不在模型内。

## 动作约束与候选生成

`WAIT` 始终允许。出牌需要满足：槽位有效、卡牌已支持、圣水足够、坐标有限且位于竞技场；兵种和建筑只允许落在我方区域 `y>=17`，法术可以覆盖整个场地。MVP 没有建模敌塔被拆后扩大部署区域。

候选来自左右桥头、塔前、中央拉扯点，以及敌方单位附近的防守位置。远程兵会尝试保持距离；法术候选包含单体位置、群体中心和敌方公主塔；建筑候选是中部拉扯点。候选去重并执行合法性过滤。候选数量随场上单位数变化，没有遍历全部连续坐标。

## 前瞻目标函数

对每个候选 `a` 重建两种假设并向前模拟 `H=8s`：

1. 敌方圣水取区间下界，期间等待。
2. 敌方圣水取区间上界，使用一个固定的规则响应策略，每 2 秒尝试动作；候选手牌从先验的另一段采样。

这是两个压力测试假设，不是严格 minimax，也不是对手所有可行动作的搜索。我方只执行初始候选，然后在该次 rollout 中等待。真实主循环在下一个观测周期重新搜索，因此属于滚动前瞻控制。

令 `V_j(a)` 是假设 j 在时间窗末端的状态价值，当前评分：

```text
Q(a) = 0.7 * mean_j V_j(a) + 0.3 * min_j V_j(a) - 0.04 * card_cost(a)
a* = argmax_{a in legal_candidates} Q(a)
```

`V` 由以下项组成，代码与这里一致：

- 我方/敌方塔的归一化剩余血量差：公主塔权重 7，国王塔 12；拆塔额外价值分别为 16 和 100。
- 场上单位剩余圣水价值差：`cost / count * hp_ratio`，系数 0.42。
- 双方剩余圣水差，系数 0.22。
- 接近敌塔的推进威胁，系数 0.38；敌方接近我塔的威胁惩罚，系数 0.8。

这些是透明、可调的启发式系数。死亡单位不再计入场面，群体单位按数量均摊卡费，避免三只亡灵被误算成三张亡灵卡。

## “最优”的可验证含义

当前只能验证：给定近似状态、有限候选、8 秒窗口和两个假设，返回最高评分的合法候选。无法保证全局最优；真实视觉误差、模拟偏差、隐藏信息、搜索范围与短时价值函数都可能改变排序。

改进顺序应是先校准观测和动力学，再扩展响应采样及多步搜索。直接增大网络并不能修复错误的对手信息或游戏规则。

## 学习问题

当前 `learning.py` 用搜索结果作为标签，训练候选动作的线性 softmax 排名器。特征包含卡牌 one-hot、圣水、费用、落点、局部空/地面威胁、法术覆盖价值和等待交互项。按整场对局划分训练/验证，避免同一局相邻帧跨集合。

后续可将同样接口接到模仿学习、离线 RL 或带循环记忆的 PPO。学习阶段需要独立报告动作一致率、等待比例、出牌帧一致率和对局强度；高等待比例会让“总准确率”显得过高。
