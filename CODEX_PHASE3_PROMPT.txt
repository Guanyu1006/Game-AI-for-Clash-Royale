三、落实10项改进

第1项：让学习策略获得可信的战场观察

目标：训练输入能表达来袭部队、集群、建筑、塔与公开出牌历史，同时保持玩家信息边界。

要求：
- 在现有battlefield接口上建立版本化的玩家观察schema。区分公开可见、由公开历史推断、未知和研究oracle字段。
- 处理实体身份、所属方、类型、位置、HP、存在/消失与时间；缺失值保留unknown/mask，不填成真实的0。
- 不能将所有原生对象直接认定为玩家可见。审计隐身、地下、生成与瞬态对象；先声明并验证受支持的普通卡牌/机制范围，再扩大。
- 无法证明可见性的对象不能进入宣称公平的主策略输入。允许单列明确标记的研究观察实验，但数据、模型和结果必须分开。
- 对手手牌、精确圣水、私有轮转、原生隐藏冷却、未来source命令等不得进入actor特征或合法mask。Oracle可用于监督目标、诊断，或显式独立的critic/teacher实验，不能成为部署actor的额外输入。
- 原生实体ID只能用于同局追踪；避免模型通过跨局ID、文件路径、质量标记或重建来源记忆结果。

验收：
- 保存可人工核对的动作前观察样例与对应画面/原生记录。
- 验证在公开历史相同的前提下，改变敌方私有状态或未来source后缀不会改变actor输入与mask。
- 验证跨reset清空历史与追踪状态；未见/缺失字段处理一致。
- 至少形成一条真正使用新观察的训练—保存—加载—原生运行链路。

第2项：扩展动作覆盖与有效出牌数据

目标：获得能够正常轮转的卡组和足够的真实出牌监督，消除仅靠WAIT行数达到数据量目标的问题。

要求：
- 从一套明确受支持的固定版本8卡组开始，逐步验证普通部队、建筑和法术；特殊技能、进化和形态单独处理，不以普通牌接口静默代替。
- 明确费用、手牌就绪、落点、己方部署区域及可观察的特殊规则。区分affordability与完整合法性，不利用隐藏状态决定mask。
- 保留planned、queued、injected、consumed、rejected、unknown等反馈。入队/注入不能直接计作成功出牌。
- 先做少量关键部署夹具和完整轮转验证，再扩大来源批次。记录不支持牌与失败分母。
- 主训练集可来自兼容、可追溯的原生重建或原生自采；专家、规则teacher和其他策略产生的数据分别标记。不得把弱视觉推断标签命名为原生确认。
- 第一批学习里程碑目标：至少50个合格独立整局、2,000次合格出牌；validation和test各至少10个独立整局。每张纳入主评估的卡至少20个监督正例，并单列稀缺牌。
- 这些是本轮数据覆盖门槛，不保证策略强度。若不能满足，报告实际差额及原因，优先修转换/兼容性/采集，不复制帧、镜像局或重演局凑分母。

验收：
- 证明支持卡组可以连续轮转，保存多次原生确认出牌记录。
- 报告原始/筛选后整局数、出牌数、WAIT数、各牌/卡组/来源质量分布。
- 同局换边、裁片、重复采集和不同重建假设必须同组切分。保留既有正式验收集的原用途，另冻结本阶段训练与测试清单。

第3项：增加历史记忆与可解释belief

目标：学习使用过去事件，先实现recurrent BC，再判断是否需要RSSM。

要求：
- 基线使用小型GRU或同等序列模型；输入当前公开观察、上一动作、实际执行反馈、双方已发生事件与经过时间。
- 复用第一阶段圣水区间与轮转思想，但费用、再生速率和特殊轮转必须来自当前版本，不能复制旧引擎时间表。
- 对公开历史推断输出区间、分布或置信度；不能把对手未知牌组和未展示手牌填成已知。
- sequence按整局组织，保存padding、burn-in和loss mask。训练片段不得跨局；运行时隐状态仅随当前实际观察更新。
- 对比单帧、显式belief、GRU及GRU+belief。小Transformer作为可选后续对照，不能同时扩模型和改全部训练条件后归因给记忆。

验收：
- 在当前观察相同、过去公开事件不同的配对样例中，确认模型确实获得不同历史信息。
- 未来事件不变性、reset隔离和在线/离线隐状态更新一致。
- 报告序列长度对应的真实秒数、推理延迟和整局指标。

第4项：统一真实时间与等待建模

目标：使训练采样、动作标签和运行控制具有一致的时间含义。

要求：
- 清楚保存source时间、engine tick、观察采样tick、请求/计划tick、确认执行tick、实际经过时间，以及已知/未知的点击与部署语义。
- 核实当前0.5秒导出、1秒控制的差异。先统一为一个固定控制节拍，供主要消融共用；选择理由与实际反应延迟写入配置。
- WAIT保留“采样间隔未记录出牌”的标签来源，不能默认解释为人类明确选择等待。
- 若对出牌窗口过采样，保存采样概率/权重；概率校准和正式指标按冻结的自然时间分布计算。
- 另做可变等待时长或事件hazard头的独立实验。等待期间继续处理环境与对手事件；真实交互中不能暂停对手来等模型。
- 可变时长转移显式接收dt；奖励和折扣按实际经过时间定义。不能直接照抄Dreamer的15步或gamma，而不换算控制频率。

验收：
- 检查动作前观察、同tick事件顺序、延迟与时间单位。
- 比较固定节拍与可变等待的反应误差、出牌频率和推理成本。
- 提供带预先声明时间容差的出牌事件precision/recall，禁止事后扩大容差提高成绩。

第5项：采用卡牌条件的位置分布

目标：学习“何时出牌、出哪张牌、下在哪里”，减少多峰落点被平均的问题。

要求：
- 实现条件策略：是否出牌/动作类型 → 卡槽或卡牌 → 该牌位置；特殊技能使用独立且受支持的分支。
- 第一版优先比较卡牌条件网格概率图与现有2D sigmoid+MSE。网格精度由版本坐标约定确定，可选格内偏移。
- 明确原生坐标、tile、屏幕像素、玩家视角的转换与逆转换；不把不同来源的18×32、32×18或像素坐标直接拼接。
- 位置mask依赖玩家可获得的规则与信息。WAIT、无位置技能和未知落点不计算普通位置loss。
- 保持训练标签与在线执行使用同一转换；动作返回前后同时保存原始坐标、标准坐标与实际反馈。

验收：
- 按卡牌类型报告位置负对数似然、距离误差、合法率及出界率。
- 分开报告“所有真实出牌”与“卡牌选择正确时”的位置表现。
- 用具有多个合理落点的样例检验模型分布；不能仅凭平均坐标误差断言策略改善。

第6项：修正评估路径并冻结可信基线

目标：离线指标对应实际部署的决策规则。

要求：
- 核实model_g_variant的play bias、argmax/采样、mask、坐标取整与推理配置。
- 抽取共用推理/动作后处理逻辑，使离线评估和部署调用一致。训练loss可以使用未加偏置的logits，但要与部署指标明确区分。
- 保留历史模型与结果，生成新的评估文件，禁止覆盖旧指标后宣称从未存在偏差。
- 所有偏置、阈值、温度与模型选择只能用train/validation确定；test不用于调参。
- 基线至少包括：全WAIT、随机合法动作、现有规则、对齐后的当前BC、在新数据上重训的单帧BC。
- 主指标包含出牌事件PR、卡牌正确率、条件位置误差、合法/消费确认率、拒绝与unknown、整局胜负、循环锁死、关键漏防、推理及端到端延迟。单列仅WAIT合法和可以出牌两种情境。

验收：
- 在同一批输入上，离线评估与部署预测逐项一致；随机策略保存并复现RNG状态。
- 原生先运行至少10局闭环smoke。
- 最终候选与对齐基线各运行至少50个相同的冻结对局配置，覆盖换边和至少两类对手；预算允许再扩展。记录配对结果与不确定性，不将小样本差值写成确定提升。
- 只按原生实际反馈统计出牌；故障、超时、截断和失败保留总分母。

第7项：建立三个外部数据来源的适配层

来源：
- https://huggingface.co/datasets/Cochon123/clash-royale-replays
- https://huggingface.co/datasets/chrisrca/clash-royale-tv-replays
- https://github.com/wty-yy/Clash-Royale-Replay-Dataset

要求：
- 每个来源先固定revision、文件hash、许可与schema，再取小样本人工审计，估算下载/解压/缓存预算，分批扩大。不要整库下载TV Royale。
- 保留不可变raw，统一中间schema包含来源ID、版本、玩家视角、时间/坐标原值、转换版本、动作语义、奖励/终止语义和质量理由。
- Cochon：区分旧raw、cleaned-legacy和新snapshot；处理HTML/JSON混合schema；出牌事件缺少连续战场状态，ghost外推和塔血弱标签分别标记。
- TV Royale：区分原始帧与各加工Parquet；审计card/x/y和前后帧对齐；缺失坐标独立mask；无时间戳时不能用frame_id乘固定帧率生成精确dt。
- wty：先检查项目已有两个样本，审计state/action/reward、视觉误差、offset、HP奖励、RTG和真实终止；不把最后出牌自动当游戏结束。对object NPY先审计并安全转换，不在主训练进程直接加载不受信任pickle。
- 无共同battle ID或可靠匹配证据时，不能把三个来源拼成同一对局的图像、动作和状态。
- 版本不兼容的数据只用于明确的预训练/辅助任务或分组实验，不能当当前版本动力学真值。
- 弱标签作为带质量权重的辅助数据；原生重建、原生自采、官方画面测量和规则外推保持不同来源等级。

验收：
- 每个来源交付可追溯的小型转换样例、schema验证和排除统计。
- 用至少一个适配来源实际运行一项适合它的数据实验，并比较是否改善既定验证指标。来源不适用时给出证据，不强行计入主训练集。
- 检查跨来源近重复、同局派生数据分组、未来信息泄漏和版本错配。

第8项：对手建模与策略池

目标：策略能面对多个合理对手，并能表达对未知行动的估计。

要求：
- 使用公开历史学习下一次对手出牌/时机或类别分布；输入不得包含对手真实手牌与精确圣水。
- 对比不显式建模对手、规则belief，以及辅助对手预测三种方案。
- 策略池至少包含随机合法、现有规则、已有学习策略或其历史快照；训练与评估对手清单冻结并保留未见对手。
- 世界模型可学习固定对手分布下的转移，也可显式条件于双方动作；声明假设。想象时不能读取回放中的真实未来对手命令。

验收：
- 对手预测报告NLL、校准与类别覆盖。
- 在未见对手与卡组上报告整局表现和退化；与同预算无对手头模型比较。
- 不把随机latent的采样多样性当作对手泛化证据。

第9项：短期结构化世界模型

目标：先证明模型具有有用的短期预测能力，再让它影响策略优化。

要求：
- 先训练小型动作条件序列模型；RSSM作为候选，与更简单的确定性循环预测模型比较。
- 输入公开状态、历史、实际执行动作、时间；预测实体状态/存在变化、塔血变化、资源、奖励和真实terminated/truncated。使用对象集合或等价可变实体表示。
- 第一阶段不要求像素decoder。若使用像素或oracle辅助目标，另记作用、权重和信息边界。
- 不必先恢复每次伤害完整因果流；缺失和弱监督要有mask。模型预测目标的来源与置信度可追溯。
- 同时报告teacher-forced一步预测和不读未来观察的open-loop多步预测。只用posterior连续纠正的结果不能冒充自由rollout准确度。
- 先评估0.5、1、2秒，再按结果扩至3、5秒；对照保持状态、线性移动/简单规则外推。
- 特别检查接战、塔伤、死亡/生成和关键防守局势。训练loss、画面相似和实际动作排序分别验收。
- 用小规模原生重置+相同前缀重演构造候选动作对照，记录恢复成本与对手假设；不假装已有快速fork。
- 在validation确定预测门槛、模型和不确定性处理方案，冻结后才评估test。随机latent不能直接当校准置信度。

验收：
- 保存checkpoint、训练曲线、真实序列预测、失败案例和多时距误差。
- 至少两个预测时距优于预先声明的简单基线，同时检查关键塔伤/死亡指标是否退化。
- 提供候选动作排序与原生短程结果的对照；分别报告已覆盖动作与分布外动作。
- 若未通过，保存失败诊断并禁止该模型进入正式想象策略；预测实验本身可以如实交付失败结果。

第10项：策略蒸馏与受控想象训练

目标：把有效teacher或预测模型转化成便于运行的actor，并验证真实闭环收益。

要求：
- 至少实现并运行一次策略蒸馏对照：teacher可以是已验证规则或受支持的短程规划器；学生只接收部署时可用输入。声明teacher的信息权限及质量。
- 近似旧引擎teacher可作预训练对照，不能作为当前原生动力学真值。不得因为搜索成本高就伪造原生分叉。
- 第9项预测验证通过后，再做小模型、短horizon的Dreamer式想象actor–critic试验。先固定版本、支持卡组和对手分布；不直接移植200M模型。
- 正确区分真实posterior与想象prior；imagined rollout不读取未来真实观察、真实未来对手动作或oracle隐藏状态。
- 奖励、continuation和折扣约定保持一致，避免重复乘discount；真实截断与自然终止分开。
- 使用真实交互补充自己策略访问的状态，明确专家分布外动作限制、短rollout或保守处理，记录模型被策略利用的失败。
- 对照同等数据、真实交互和计算预算的recurrent BC/蒸馏策略。若尝试PPO，复用同一观察与动作契约，不借更丰富输入制造算法优势。

验收：
- 学生模型新进程加载，至少10局原生闭环smoke，最终候选按第6项配对评估。
- 分开报告真实环境步数、想象步数、训练时间、运行延迟与对局表现。
- 未过第9项门槛时，第10项仅交付蒸馏对照及想象训练的未进入原因；不得宣称Dreamer已验证。
- 训练能运行、模型预测达标和棋力提升是三种不同结果。任何一种未达都如实记录，不以更名或过滤失败制造成功。

四、共同消融与执行效率

1. A：新冻结数据上重训的单帧BC；B：A+可信战场；C：B+历史记忆/belief；D：C+卡牌条件位置；E：D+短期预测辅助任务。
2. A—E使用相同来源切分、支持动作范围、固定时间节拍、对手与评估配置。可变等待、外部数据预训练、对手头、RSSM和想象训练分别增设消融，避免一次改变所有因素。
3. 旧模型在旧数据上的结果作为历史参考，不与新训练集上的A—E直接比较归因。模型选择用validation；test不反复用于选择。
4. 先小样本验证端到端，再扩大。所有候选先做离线指标和10局闭环，最终有价值的候选才扩大配对对局；不要把每个超参数组合都做昂贵原生大评估。
5. 对主要学习结论尽量使用至少3个独立训练seed；原生评估可以先筛选再复核。若资源不足，保留单seed限制，不能把同一checkpoint短续训称为独立训练。
6. 本地生成数据、转换与训练任务有任务ID、不可变配置、原子写入和断点恢复。主动中断并恢复一次，检查重复计数、半成品和状态隔离。

五、交付、验收与完成口径

1. 提供统一入口，覆盖doctor、baseline-audit、data-audit、convert、collect/reconstruct、export、train、evaluate、predict-model、play与acceptance；名称可调整，但命令必须真实可运行。保留原平台入口。
2. 为10项建立 outputs/phase3/acceptance.json：逐项关联实现、实际命令、输入/配置指纹、日志、输出hash、指标、通过/失败/未验证与原因。验收不能只检查文件存在或硬编码passed。
3. 保存可见性与数据契约检查、真实训练checkpoint、原生执行反馈、至少一段候选策略完整对局画面、A—E对照、模型多步预测和失败复现样例。
4. 新增中文教程说明观察字段、隐藏信息、历史状态、时序与动作转换、三来源质量、数据量口径、训练和加载命令、评估指标及故障恢复。
5. 最终报告必须分别列出：
   - 实际支持的版本、卡组、动作与机制；
   - 原始/合格整局和出牌数量，WAIT分布及train/validation/test分母；
   - 10项各自完成程度，以及哪些只有实现、哪些有实验达标；
   - 相同条件下哪些改动改善、无改善或退化，统计与样本限制；
   - 原生胜负、动作消费、拒绝/unknown、锁死、延迟与资源成本；
   - 世界模型一步/open-loop误差，是否获准进入想象训练；
   - 尚缺的独立官方真值、可见性范围、外部来源或运行能力。
6. 不承诺必须产生胜率提升。不得把失败、预算停止或外部阻碍写成全部完成；保留可直接继续的命令。若想象训练未过前置门槛，明确该部分未验证，交付已完成的蒸馏与预测实验。

执行时先完成基线核实与评估路径修正，冻结配置，再按上述依赖持续推进。普通、可逆的项目内实现与验证自主完成；遇到阻碍继续真正独立的工作，不用等待逐项催促。
