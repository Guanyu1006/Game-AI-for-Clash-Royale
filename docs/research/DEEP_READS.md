# 12 篇核心论文的正文精读与实验设计

以下分析依据已保存 PDF 正文的方法、实验及限制章节。PDF 页码指文件页序号；相应 `references/library/<id>/extracted.txt` 用 `--- PDF PAGE n ---` 分页。作者实验与我们提出的迁移方案分开；这份文档不宣称复现作者结果。全条目元数据、校验值和本机解析状态见 [PAPERS.md](PAPERS.md)。

## 1. SEAT：先分解动作，再审视证据

来源：[IJCAI 2019 原文](https://www.ijcai.org/proceedings/2019/0631.pdf)。精读 PDF 第 3-6 页，算法 1、表 1/2、§3/4/5。

状态并非原始截图：作者将血量、单位类别和阵营映射到 32×18 网格，再拼手牌特征。selection 输出四张卡和空动作的五个 Q 值；attention 使用敌方状态卷积特征确定网格，不能把它等同于今天的大型语言模型 attention。选卡与落点解耦有效减少组合空间，但落点模型若遗漏拉扯/法术边界，好的选卡也可能执行失败。

作者在 Windows Lua 模拟器使用八张抽象卡，同卡组对称对战。表 2 报告对进攻规则、防守规则、决策树对手的胜率分别为 90%、90%、70%，每对只打 10 局。这个样本小，且没有原游戏轨迹一致性证据。论文的出牌惩罚与拆塔奖励是特定 reward，不应当直接搬到当前原生引擎后称为相同任务。

迁移方案是把 `royale_lab/policies.py` 的候选卡选择和部署坐标分开排序，以同样的候选数量/延迟预算比较联合候选打分。应测非法动作、法术空放、可见威胁漏处理和配对胜率；调 `royale_lab/rewards.py` 时同时看终局胜率，防止为了少出牌而提高奖励。SEAT 适合作为建模起点，不能成为全卡引擎的真实性证书。

## 2. KataCR：WAIT、视觉融合和真实闭环

来源：[arXiv 2504.04783v1](https://arxiv.org/abs/2504.04783v1)。精读 PDF 第 4-8、10-14 页，§3、§4.3、§5，表 2/3。

论文链路是画面采集、检测/OCR、状态/动作/奖励融合、离线策略和设备操作。105 个固定卡组专家对局共 113981 帧，仅 4.01% 为动作帧。普通逐帧分类容易大量输出等待；作者引入未来最近动作的 delay 标签，并重采样动作附近帧。delay 上限为 20 帧，超出窗口不能被解释为真正已知的未来出牌时刻。

检测训练使用生成切片，而 6939 张、116878 框的验证集来自人工标注真实视频；这是值得复制的分布隔离。表 3 的策略验证每模型 20 局，最高胜率 10%，最大奖励和最高胜率对应的模型配置不同。作者测得决策平均 120 ms、融合 240 ms；这是其 Ubuntu/GPU/手机链路，不能代替本机 p95。论文结论明确尚不能稳定战胜内置 AI。

本项目应在 `royale_lab/session.py` 保留观测、推理、动作接受、状态变化的时间戳；像素适配在 `royale_ai/perception.py` 记录每个观测字段置信度，确认出牌事件才更新 `royale_lab/memory.py`。数据按整局切分，报告 WAIT 比例、出牌帧准确率、时机误差和实际接受动作数量。应做 delay 标签/不重采样的消融，并用真实留出帧评价召唤事件误差；合成截图只能检查接口。

## 3. POMCP：搜索的初始状态来自信念

来源：[NeurIPS 2010 原文](https://papers.nips.cc/paper_files/paper/2010/file/edfbe1afcf9246bb0d40eb4d8027d90f-Paper.pdf)。精读 PDF 第 3-7 页，§3/4/5，算法 1。

POMCP 的树节点是动作/观测历史 `h`，不是某个已知完整状态。每次模拟从信念 `b(s|h)` 采样状态，再调用生成式模型 `G(s,a)→(s′,o,r)`。UCT 选择兼顾价值和探索的动作，rollout 估计未展开后续；收到真实新观测后保留对应历史分支，并更新粒子。理论收敛依赖真实信念和足够模拟，不能推出几十毫秒、近似模型的最优策略。

作者通过模拟观测匹配更新无权粒子，同时讨论 particle deprivation 和 reinvigoration。对于皇室战争，精确匹配连续画面是不现实的，应先用结构化事件及容差模型。圣水回升阶段、看到的出牌费用和轮转历史可以排除不可能假设；未知卡组/漏检则要求恢复粒子而非把信念强制压成唯一答案。

迁移点是 `royale_lab/memory.py` 的卡组/圣水不确定性和 `royale_lab/policies.py` 的前瞻对手假设。后端快照只能用作调试或由可见事件重建模型；不能把真实对手手牌复制给主策略。先在有隐藏手牌的测试场景比较固定对手、区间信念、多粒子搜索，报告真值落入圣水区间比例、部署反制胜率和同一延迟预算的收益。粒子数量增加若只拖慢决策，需先修观测模型。

## 4. PPO：更新稳定和闭环正确是不同问题

来源：[arXiv 1707.06347](https://arxiv.org/abs/1707.06347)。精读 PDF 第 2-7 页，式 7、算法 1、§6。当前保存的 PDF 正文标记 v2。

PPO-Clip 的目标为 `E[min(r·A, clip(r,1-ε,1+ε)·A)]`，其中 `r=πnew(a|o)/πold(a|o)`。剪切去掉部分过大更新的收益动机，并允许同批 on-policy 数据反复优化；它不保证所有状态的 KL 被硬约束，也不保证 reward 越高胜率越高。价值损失、熵和优势估计共同影响实际训练。

本任务长局、大量 WAIT 和终局胜负会增加信用分配难度。必须区分真正终局与训练时间截断，正确处理 bootstrap；递归策略还需 hidden state 跨局清零。动作被后端拒绝时，不能把日志中“计划动作”当作“执行动作”去计算回报。

`royale_lab/learning.py` 负责训练/checkpoint，`royale_lab/session.py` 负责实际对局。优先用固定种子/卡组和三类对手验证零非法动作、loss/entropy/KL 与 checkpoint 推理。短程训练有权重变化和完整对局说明入口跑通；棋力需要独立 100 局以上配对评价，且冻结测试集不参与模型选择。再研究 horizon、GAE λ 和终局权重，而非一开始扩大网络。

## 5. Invalid Action Masking：同一分布用于采样和学习

来源：[arXiv 2006.14171v3](https://arxiv.org/abs/2006.14171v3)。精读 PDF 第 2-6 页，Proposition 1、表 1/2、实验图 2。

将非法 logits 设为很大负值并重新 softmax，得到有状态依赖的 masked policy。论文证明该变换可微并对应有效策略梯度；非法维度梯度为零。只按 masked distribution 采样，却用 unmasked log-prob 更新，是不同的“naive masking”方案，作者实验观察到较大 KL。mask 不只是推理时丢弃一次非法操作。

作者在 MicroRTS 资源采集任务用分解动作，扩大会地图令非法选项比例上升；它不是全战斗强度证明。负奖励惩罚非法动作存在探索成本，通常不如直接正确屏蔽。论文使用四随机种子和多个地图，这启发我们对动作空间规模做控制实验。

本项目的 mask 来自自身圣水、手牌、区域和已知技能冷却；不应读取对手隐藏手牌。`royale_lab/backend.py` 验证真实合法性，`royale_lab/policies.py` 控制候选；`royale_lab/learning.py` 必须在采样、log-prob、熵和评价时一致应用 mask。WAIT 保证至少一个有效动作，过期观测仍可能被执行器拒绝，应另计 stale observation 和非法策略两种错误。先过接口测试再做“mask vs penalty”消融。

## 6. DAgger：在学习者造成的失败局势查询专家

来源：[arXiv 1011.0686v3](https://arxiv.org/abs/1011.0686v3)。精读 PDF 第 1-5 页，算法 3.1、Theorem 2.1/3.1/3.2。

普通 BC 在专家访问状态分布训练，但自身一次错误会把后续状态带离训练分布，误差可累积。DAgger 让当前学习者 rollout，在访问状态上查询专家，聚合旧新数据再训练；初期可混合专家，最终应主要访问学习者自己的状态。它不是简单地把原专家数据多训练几轮。

理论界限依赖有界损失、no-regret 学习以及专家误差/成本假设；有限样本、神经网络优化和有误差的搜索专家都不自动满足这些前提。作者使用驾驶、Mario 与 OCR 序列任务，不能推导此项目搜索教师全局最优。

迁移到 `royale_lab/learning.py` 时可将预算搜索作为可查询教师：对 BC 完整对局保存的失败快照重新标签，连同原专家数据训练下一轮。`royale_lab/backend.py` 快照用于重放，教师必须使用同样的可见观测/信念。记录查询毫秒数、标签候选集/搜索预算和教师 checkpoint。评估 BC 与 DAgger 的跨种子胜率、出牌帧错误和独立失败场景恢复能力，不以训练集标签准确率代替结果。

## 7. IQL：学价值与提取策略分离

来源：[arXiv 2110.06169v1](https://arxiv.org/abs/2110.06169v1)。精读 PDF 第 3-7 页，§4.1-4.4，式 5/6/7、算法 1。

IQL 先对数据内 `Q(s,a)-V(s)` 做不对称平方 expectile regression，再以 `r+γV(s′)` 拟合 Q，最后按 advantage 指数权重做 BC。关键是 value 的高 expectile 针对数据动作差异，而不能对幸运随机转移也取乐观 expectile；论文为此分开 V 与 Q。训练价值阶段不需要对新策略产生的未见动作做显式 max。

论文在 D4RL 包括需要拼接次优轨迹的 AntMaze 中测试，并展示在线微调。它可以重用已有轨迹，却不能保证从单卡组且从不反制空中的数据中学会空中反制。大的权重温度/expectile 也可能令少量有噪标签主导。

本项目可将 `(visible_history, candidate_action, accepted, reward, next_visible_history, done)` 存为离线样本；候选 ID 必须版本化，不能每次排序后把 ID 语义改变。先在 `royale_lab/learning.py` 增加 IQL 训练器、在 `royale_lab/rewards.py` 固定奖励，再比较 BC/IQL。同数据、同卡组划分和同执行 mask 下测收益；每次换模拟规则要重算回报，避免旧数据混进新动力学。

## 8. CQL：保守价值的适用边界

来源：[arXiv 2006.04779](https://arxiv.org/abs/2006.04779)。精读 PDF 第 3-6 页，§3.1/3.2、Theorem 3.1/3.2。

CQL 在 Bellman fitting 之外压低某些动作分布的 Q，并提高行为数据动作的相对价值。式 1 的逐点下界与式 2 的策略期望下界不是同一个保证；论文特意说明，放宽版本不必逐点低估所有动作。深度近似和有限数据实践更不能称为绝对保守安全。

在大落点空间，价值网络可能夸大从未部署过的坐标；CQL 是对此类离线外推的备选方案。若我们只保存规则候选而没有被淘汰动作标签，应先量化每张卡/区域/时机的数据覆盖，再决定正则强度。过强保守可能永远等待或重复低风险弱动作。

应用在 `royale_lab/learning.py` 的候选价值学习。正则求和和归一化只针对当前合法动作；测试也应用相同 mask。比较 Q 预测与真实快照 rollout 的排名、数据内/外候选塔伤误差、在线胜率。对于视觉有噪事件，应保留接受反馈并做数据清洗；从错误状态学习的“保守 Q”没有机制校准能力。

## 9. Decision Transformer：目标回报不是未来信息

来源：[arXiv 2106.01345](https://arxiv.org/abs/2106.01345)。精读 PDF 第 4-10 页，式 2、算法 1、§4/5。

DT 使用 `(return-to-go, state, action)` 历史 tokens，训练中利用已结束轨迹的实际后续回报监督；执行时输入人为设定的目标回报，并每步减去已得奖励。执行器不能将该局真实未来回报填入输入，否则是泄漏。论文主要预测 action，原方法不是完整状态转移模型。

作者实验包含 Atari、离线控制和长时任务。某些任务更长上下文有益，其他任务不一定；高于数据的目标回报有时可外推，却没有普遍保证。Transformer 能记住历史，不代表它知道未曾观察的敌方当前手牌。

对本项目，`royale_lab/learning.py` 应使用可见历史和固定版本的卡/坐标/delay 编码；WAIT 监督必须单独加权或按事件级序列处理。KataCR 已提供直接相关 delay 设计。先比较去掉 return-conditioning、不同上下文长度和 WAIT 重采样。评价用完整未见对局、目标回报可实现性、动作时机 MAE 与 p95 延迟；将同局帧随机拆成训练/验证会使历史泄漏。

## 10. MuZero：价值等价模型不是精确战斗模型

来源：[arXiv 1911.08265v2](https://arxiv.org/abs/1911.08265v2)。精读 PDF 第 2-5 页，图 1、§3 及附录搜索伪码。

MuZero 将观测历史编码为潜在状态 h，动态 g 接收潜在状态/动作并预测下一潜在状态及奖励，预测 f 输出 policy/value；MCTS 用这些量改进策略。模型训练对齐搜索策略、实测奖励与终局/多步价值，而非强制还原每个单位的真实位置。这是高效规划的优势，也是不能把它当官方机制复刻的理由。

作者展示 Atari 与棋类实验，既有大量训练，也有搜索成本。对实时卡牌游戏，还需要将等待长度及对手行为作为模型条件；同一己方动作在不同敌方策略下不会产生唯一可靠未来。

在可靠后端建立后，可新增 world-model 接口替换 `royale_lab/policies.py` 的部分真实快照 rollout。保留真实 `royale_lab/backend.py` 作为验证基准，测 1/2/5/10 秒塔伤、死亡/召唤事件和候选排序误差。低 loss 不足以说明搜索安全；模型自我搜索可能放大偏差。首要消融是同一延迟预算下“原生 rollout / 潜在模型 / 混合校验”的胜率与灾难性漏防率。

## 11. PSRO：避免把打赢固定对手当泛化

来源：[arXiv 1711.00832v2](https://arxiv.org/abs/1711.00832v2)。精读 PDF 第 1-5 页，§3、算法 1、joint-policy correlation 定义。

PSRO 将策略本身当经验博弈中的选项：对已有池计算 payoff，求 meta-strategy 混合，然后训练近似最佳响应并加到池中。它推广 Double Oracle，但 RL 的响应不是精确 oracle，当前池也不是所有可能对手。随机、规则、搜索和历史 PPO 都可以成为池成员。

作者强调 independent RL 对训练伙伴过拟合，并在部分可观察合作/扑克设置研究。总体平均胜率可能隐藏克制循环；新策略只打赢当前一个规则对手可能削弱对旧对手的能力。

本平台可在评估入口构建成对策略矩阵，交换红蓝边、固定 seed/deck，再把 checkpoint 与策略配置纳入池。`royale_lab/session.py` 保证每局自动 reset，训练端 `royale_lab/learning.py` 采样对手池。先用均匀/近期/基于失利的采样比较，再增加元求解器。报告最差对手胜率、跨卡组表现和矩阵置信区间；没有强最佳响应评估时，不应称为低 exploitability 或 Nash 策略。

## 12. ByteTrack：追踪身份与出牌事件分离

来源：[arXiv 2110.06864](https://arxiv.org/abs/2110.06864)。精读 PDF 第 3-6 页，§3、算法 1、实现与实验章节。

BYTE 将检测分为高分/低分：先关联高分框，再把未匹配轨迹与低分框关联，以恢复遮挡目标；低分新框不能随意被当作新轨迹。Kalman 预测与 IoU/外观匹配是接口，不是一种万能对象身份推断。作者在 MOT 行人数据上的结果证明其特定追踪效果。

游戏中多个同卡精灵相似，召唤、死亡、复活和转化会破坏普通行人假设。一个漏检后重现框可能是旧单位，也可能是真新单位；把每次新检测都计作对手下牌，会把圣水信念越算越错。

适配 `royale_ai/perception.py` 时先加 card-class、阵营和最大速度 gate，保留 track lifecycle/置信度，再将高置信群体生成事件交给 `royale_lab/memory.py`。标注独立真实短视频，量化 ID switches、漏召唤/重复召唤、死亡时刻误差和圣水区间覆盖；用这些指标再看策略胜率。新模型 mAP 高但事件误差更差时，不能直接替换闭环感知。

## 正文精读后得到的实现优先级

先修闭环与信息边界，再修动作空间和引擎误差，再收集整局数据，最后比较策略方法。上述迁移建议是待验证研究假设。一次近似模拟器实验只能支持同版本近似环境内的结论；到官方游戏的迁移必须再有真实视觉/动作/轨迹证据。
