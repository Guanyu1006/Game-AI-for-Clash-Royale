# 后续路线与优化定位

更新于 **2026-10-14（Asia/Shanghai）**。当前可运行的研究平台已经具备原生战斗引擎、可见观测、动作反馈、本地服务、回放、BC/PPO 训练和冻结 700 局评估。最终原生测试为 740 cases：739 通过、1 项预期失败，8413 assertions 中 1 项预期失败；平台 21 个测试通过。下一轮优先补足可量化的模拟误差和决策表示，再扩大训练规模。搜索 63%、BC 48%、PPO sampling 37% 是当前四卡组/三对手条件下的基线；它们不是完整皇室战争的验收结论。旧 MVP 路线已保存至 `outputs/archive/mvp_experiment_docs`。

主工厂数值外置已完成：`data/platform/balance_v2.json` 的 25 类字段真正改变结算，173 个 registry 行中 171 行支持修改，41 个进化行区分普通/进化数值；34 项数值回归及独立接口复查通过。默认物理经 100 局、每个新变体 169,994 个完整状态点核对为零差异，既有 700 局继续保留。后续外置工作针对 [排除清单](../data/platform/unsupported_numeric_parameters.json) 中的 **68 个 CardStats 数值成员、36 个 effect 类内部参数清单**以及塔兵种/子实体等；这两个数是源码库存，不是机制或卡牌覆盖分母，也不意味着所有内部常量已穷尽。

## 第三优先：提高搜索收益并公平比较算力

目前 search 对 greedy 的配对得分差 +13 个百分点，50 组换边 bootstrap 95% 区间 +6 至 +20；响应建模相对 no_response 仅 +3，区间 −6 至 +13，尚未确认稳定收益。响应建模使 P95 从 6.283 ms 增至 16.504 ms；默认 15 ms 是软预算。

先比较固定展开数和固定墙钟两种协议，记录实际候选/分支/clone 数和超预算帧比例。再依次加入多种对手响应、信念采样、二步动作、beam/MCTS、学习 value；每次只改变一个主因素。入口为 `royale_lab/policies.py` 的 SearchPolicy 与信念模块，后端必须仍通过可见观测重建，不允许读真实敌方手牌或圣水。验收使用新冻结场景、配对区间及 P95/P99，同时保留相同算力的 no_response 基线。

## 第四优先：训练规模、对手池与泛化

当前 BC 12 局教师数据、PPO 4096 步/27 完成局，只完成工程训练通路。PPO 训练最长 180 秒，主测试最长 300 秒，而且训练对手只有 greedy。扩大训练前应对齐回合时长或明确课程学习策略，并补充未见卡组、进化/塔部队和对手版本。

建议先做 3 个独立训练 seed 的小规模 BC、BC warm-start PPO 与随机初始化 PPO，对照同一采样推理方式；通过后再增加预算。训练池纳入 greedy/search 的不同参数和历史模型，自博弈保存版本池与 Elo/交叉对战矩阵。冻结测试集至少区分：开发集、未见组合、未见对手、版本迁移；最终测试集不用于挑 epoch/调 reward。

每个实验保留配置、引擎/数据/模型 SHA、seed、训练步、完成局、终局胜负、奖励分量、WAIT/PLAY、合法率、条件 entropy、critic 指标、硬件与吞吐。除胜率外还要看不同侧/卡组/对手的失败结构。给 score difference 的区间而非只比较单个百分比；必要时按卡组/对手分层重采样，并说明多重比较。奖励变化要检查“输出出牌很多但不防守”等漏洞，不能只看训练 return。

## 下一轮应交付的最小增量

先交付一个可比较的版本：修复已知导航卡住；冻结至少 20 个基础机制/战术差分场景并解释 Poison 等剩余分歧；加入全局 critic 和分层动作模型；进行至少 3 个训练 seed 的 BC/PPO 对照；在新输出目录跑不低于当前规模的配对评估。成功标准是机制证据增加、出牌决策质量改善、无隐藏信息泄漏、执行拒绝/崩溃为零，并给出得分差和延迟代价。若收益区间跨零，保留失败实验再定位，不覆盖已有 700 局基线。

入手时先读 [EXPERIMENTS.md](EXPERIMENTS.md) 和 [PPO 行为审计](audits/PPO_BEHAVIOR.md)，再按上表的具体文件修改。每次改变动力学、编码器或候选器后，生成独立版本的训练数据与模型，保证以后能解释改进来自哪里。
