# 研究缺口、限制与可检验路线

## 哪些问题仍需证据

直接皇室战争原始论文相对少。SEAT 用抽象卡组和 Lua 模拟，KataCR 用固定卡组真实设备与少量策略对局；二者都不能证明当前全卡、进化、英雄、塔兵种规则的完全复刻。通用 RTS、棋类、扑克、机器人论文在这里属于可迁移方法，不能混算为皇室战争实证研究。

本地 C++ 引擎使大量实验可行，但路径、碰撞、首击、法术塔伤和边界误差可能改变最佳落点。若搜索只在模拟器得胜，它可能利用误差而非学到真实反制。每项机制须同时给实现覆盖与对照证据；“存在 132 卡数据”不等于“132 卡官方一致”，更不等于穷举所有组合。

真实视觉通常只给有噪单位/塔血/手牌信息。感知延迟和策略延迟会叠加，敌方手牌和精确圣水本就不可见。需要带来源、置信度和时间戳的事件，再更新信念；将隐藏状态提供给策略会得到不可部署的好结果。oracle 应独立标注。

## 按收益与依赖推进

| 优先级 | 问题 | 可执行工作 | 验收证据 | 依赖/难度 |
| --- | --- | --- | --- | --- |
| P0 | 战斗误差主导策略 | 固定版本，对桥/碰撞/首击/法术塔伤建立实际录像差分 | 单位位置/血量随时间误差与已知失败清单 | 真实可用录像，较高 |
| P0 | 状态/动作边界 | 确认隐藏敌手信息未泄漏；日志区分计划、接受与执行 | 同观测不同隐藏状态策略一致；重复动作/过期观测测试 | 已有 backend/session，中 |
| P1 | 训练样本与等待 | 搜索生成整局，按局切分，保留 WAIT/delay 及候选版本 | 出牌/WAIT 分项、数据 hash、留出胜率 | 可运行搜索，中 |
| P1 | 对手信念 | 卡组候选、轮转、圣水区间；漏事件时恢复不确定性 | 真值区间覆盖率/漏检消融 | 可見历史，中 |
| P1 | 长期评价 | 用终局+势差 reward 对照；价值网络做 rollout 排序 | 同预算100局配对/换边与回放 | 稳定环境，中 |
| P2 | 行为克隆分布漂移 | DAgger 查询 BC 访问失败状态 | 学习者局势恢复、专家成本 | 可信搜索教师，中 |
| P2 | 训练对手过拟合 | 历史 checkpoint + 三类规则策略池 | 交叉 payoff 与最差对手表现 | 多局评估，中高 |
| P2 | 视觉闭环 | 小规模真实标注、检测/OCR/追踪、事件融合 | 真帧误差、设备接受反馈与完整对局 | 设备/游戏权重，较高 |
| P3 | learned world model | 学短多步动力学，原生 rollout 校准 | 预测塔伤/召唤/死亡和候选排序误差 | 足量无泄漏数据，较高 |
| P3 | 通用卡组策略 | 扩卡组/进化/塔兵种，条件策略或序列模型 | 未见卡组与平衡版本鲁棒性 | 引擎覆盖+多样轨迹，较高 |

## 应避免的错误结论

下载源码不代表成功安装；成功编译和内部测试不代表官方一致；checkpoint 可以加载不代表训练有效；训练 loss 降低不代表棋力提高；20 局单对手胜率不代表稳定泛化；合成 mAP 不代表真帧 mAP；oracle 胜率不代表可见信息策略；参数随机化不代表消除了所有 sim-to-real 偏差。

所有报告应明确游戏版本、引擎 commit/data hash、观测路径、策略预算、对手/卡组、真实数量与失败日志。资料下载器与这份研究说明不会替主平台运行记录作证。
