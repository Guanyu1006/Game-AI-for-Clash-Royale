# 问题建模：部分可观察实时对抗

全状态s包含双方手牌/队列、圣水、单位、塔、弹道、计时与RNG；玩家只获得观测o。隐藏卡组、轮转与时机使其接近实时部分可观察随机博弈，而不是一次分类“应该下什么牌”。本地引擎虽然提供oracle，主策略不读取它。

## 动作与时间

tick0.1秒，策略默认每1秒决策。Action显式WAIT、卡槽+连续x/y、技能与delay_ticks。候选将落点离散为桥头、防御、敌群、塔等；合法性由原生引擎裁决。亚秒时机和连续落点搜索是以后扩展点。

v2恢复每tick1/28圣水，上限10；0..120s单倍、120..240s双倍、240s起三倍。默认3000tick。上游终局/加时实现有近似，见coverage；短课程max_ticks不等于官方对局规则。

## 信念与模型

Belief依据确认公开出牌扣费和时间恢复维护敌方圣水区间，记录已见牌和4卡基础周期。没有完整历史或来自screen，区间保持保守；推断事件不能冒充确认。卡组先验仍是已见牌+固定Hog补齐，不是学到的完整对手模型。

SearchPolicy分别建立低圣水等待和高圣水规则反应假设，从公开状态重建新引擎并前瞻。候选分数为0.7假设均值+0.3最差假设，扣轻微出牌费用。默认4/6秒窗口、有限候选、软墙钟预算。单位群、衍生实体、状态计时、未知队列重建有误差，因此没有全局最优保证。

## 目标、奖励与学习

rewards.utility组合双方塔HP比例/倒塔、可见单位费用与剩余HP、推进位置、自身圣水。transition_reward为0.1效用差，终局胜+10/负-10；Gym非法选择再罚0.5，不用敌方隐藏圣水作特征或奖励。

BC拟合搜索专家候选，PPO在mask分布上用GAE/clip训练。CandidateNet逐候选评分，value读取WAIT行可见状态。短训练checkpoint证明可运行，不证明收敛或强策略；等待帧高准确率掩盖出牌弱，必须分别报告。

整局划分train/validation，测试种子不同。固定场景记录胜平负/塔伤/接受拒绝/WAIT与PLAY/延迟/崩溃。结论仅适用于当前近似版本、固定场景；真实游戏迁移需要规则校准、真实视觉误差与设备执行实验。
