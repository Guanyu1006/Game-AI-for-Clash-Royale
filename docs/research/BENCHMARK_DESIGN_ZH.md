# 皇室战争 AI 系统评测调研与 Benchmark 设计草案

调研日期：2026年10月18日。适用项目：Royale Lab 当前近似模拟器、固定版本原生研究环境及第三阶段可信观测与时序策略路线。

大厂工作专题补充：[Dota 2 与 Minecraft 等研究的评价方法](BIG_TECH_GAME_AI_EVALUATION_ZH.md)，包含OpenAI Five、VPT、DreamerV3与4、SIMA 2、MineDojo、Voyager及其他代表性工作。

建议把论文主张收敛为：**在明确的游戏版本、可用信息、卡牌范围和实时预算下，系统能以可复现的方式完成对战；提出的方法能在未参与选择模型的对手和场景上改善整局表现，并由针对性的实验解释原因。** 胜率、战术能力、泛化、运行可靠性分别报告，环境正确性和信息公平性作为进入相应评测的条件。

本文中的实验数量、任务划分和阈值是设计建议；历史实现状态来自当前项目文档和代码阅读，没有在本次调研中重新运行原生对战。外部论文结果为作者报告，不能当作本项目的复现结果。调研采用直接相关研究与代表性评价方法的定向检索，不据此宣称已覆盖全部文献或证明研究空白。

## 论文主张与证据要求

| 想写出的结论 | 必须提供的证据 | 单独不足以支持结论的材料 |
| --- | --- | --- |
| 平台可复现并能支撑研究 | 版本指纹、公开契约、可重放日志、独立重启、失败分母、测评代码 | 单次演示、接口测试通过 |
| 原生环境接近目标游戏 | 独立参考轨迹或画面测量、关键机制的逐步对照、初始化与时序误差 | 引擎来自原生库、相同胜者、相同输入重复一致 |
| 方法提高对战强度 | 同轨道、同预算、同测试配置的整局比较，多个独立训练运行和不确定性 | 训练奖励上升、离线准确率高、击败随机策略 |
| 记忆或信念有效 | 当前观察相近而历史不同的任务、移除历史的对照、未见对手的整局收益 | 模型包含 RNN、隐藏量预测更准 |
| 世界模型有助于决策 | 多步预测、候选动作排序及真实闭环收益，资源预算匹配 | 一步误差小、视频看起来合理 |
| 达到某个人类水平 | 同规则、同信息和时间约束，分层招募玩家、固定协议和玩家级统计 | 赢过一位朋友、历史杯数、模拟器 Elo |
| 具有泛化能力 | 对所宣称的泛化轴独立留出，报告各轴结果 | 仅更换 RNG seed、把同一录像切成新片段 |

如果当前最强证据是环境、接口和数据工程，论文可以以研究平台和评测协议为中心。若方法消融与泛化收益充分，再以算法贡献为中心。让结果决定最终主张，不能从想要的故事反向挑选测试集。

## 游戏 AI 领域的评价方法

### 皇室战争的直接相关研究

| 研究 | 作者如何评价 | 对本项目的启发 |
| --- | --- | --- |
| [SEAT，IJCAI 2019](https://www.ijcai.org/proceedings/2019/0631.pdf) | Windows 模拟环境；固定同卡组；比较规则与决策树对手，并做模型设置实验 | 把选牌和落点分开诊断；其模拟器、卡组和规则范围限定了结论 |
| [Oracle Planner，2020 预印本](https://arxiv.org/abs/2012.12186) | 搜索器两两对战；主搜索比较每对400局；表VI报告多类代理交叉矩阵，学习代理使用5个训练seed | 采用交叉矩阵和独立训练运行；把全状态teacher与部分观察follower分开 |
| [KataCR，2025 预印本](https://arxiv.org/html/2504.04783v1) | 真实视觉与设备闭环；105局固定卡组示范；表3每项20局，最高胜率10% | 感知与整局分别评价；奖励、出牌数量、胜率分别解释，小样本用于初步验证 |

SEAT 的实验明确采用模拟环境，不能把其中数字转述成官方客户端竞技水平。Oracle Planner 的全状态搜索器能够读取普通玩家不知道的信息，适合充当特权教师或参考代理。KataCR 的结论是实现真实视觉闭环并能赢内置AI；其表中选择“前10个epoch中最高平均奖励”的方式也提醒我们，应把checkpoint选择和最终测试分开。上述三篇分别核对了正文实验设置或结果表；不同环境的胜率不构成共同排行榜。

| [DeepNash，2022](https://arxiv.org/abs/2206.15378) | 不完全信息策略、对现有程序与人类平台的评价 | 检查策略的抗针对性，区分平均强度和被特定对手克制的风险 |
| [α-Rank，2019](https://arxiv.org/abs/1903.01373) | 通过经验博弈分析策略间的非传递关系 | 先公布交叉胜率矩阵，有明显克制循环时再考虑α-Rank等补充分析 |
| [Multiagent Evaluation under Incomplete Information，2019](https://arxiv.org/abs/1909.09849) | 有限且带噪声的对局会造成排名不确定性 | 每个矩阵格子保留局数和区间；名次接近时不强行排序 |
| [Local Best Response，2017](https://arxiv.org/abs/1612.07547) | 以可计算的近似最佳应对探测可利用性 | 固定被测代理，另训攻击者；攻击者没找到漏洞不能证明无漏洞 |
| [AIVAT，AAAI 2018](https://arxiv.org/abs/1612.06915) | 在具备策略概率等条件时，用无偏修正降低不完全信息评测方差 | 优先做换边、共同初始条件；满足推导假设后才引入更复杂修正 |
| [Statistical Precipice，NeurIPS 2021](https://arxiv.org/abs/2108.13264) | 区间、分层bootstrap、IQM与性能分布 | 报告跨训练运行和任务的变动；本项目以宏平均为主，分布和IQM辅助 |
| [MineRL竞赛回顾，2020](https://proceedings.mlr.press/v123/milani20a.html) | 约束训练样本与算力，并在留出环境重新训练评价 | 比较样本效率时纳入数据、训练和搜索成本，清楚定义可用先验 |
| [GameBench，2024](https://arxiv.org/abs/2406.06613) | 多种游戏对应不同战略推理能力，并设置人类与随机参照 | 能力任务按认知需求设计，而非只统计模型整体分数 |
| [BALROG，ICLR 2025](https://arxiv.org/abs/2411.13543) | 通过多种长时程游戏评价规划、探索与空间推理 | 检查长局持续决策与错误累积，完整保存回放 |
| [VideoGameBench，2025及2026修订](https://arxiv.org/abs/2505.18134) | 实时像素整局，另设推理期间暂停的Lite模式 | 决策质量与实时部署分两种时钟评价，不能混成同一个“实时胜率” |
| [lmgame-Bench，2025](https://arxiv.org/abs/2505.15146) | 关注感知脆弱性、提示敏感性、数据污染及辅助框架 | 比较LLM时同时冻结prompt、记忆、工具和重试机制 |
| [TowerMind，AAAI 2026](https://arxiv.org/abs/2601.05899) | 塔防中的像素、文本与结构观察，不同任务难度及无效行为 | 设置多观察轨道；结构状态成绩与视觉端到端成绩单列 |
| [Kaggle Game Arena技术报告，2026年9月](https://arxiv.org/abs/2609.31473) | 多类竞争游戏及头对头竞赛，以游戏结果评价 | 维护可扩展挑战池，同时保留固定锚点，使历次结果仍可比较 |

2026年的统计工作也值得关注。[Heuristic Pathologies](https://arxiv.org/abs/2605.14261)讨论在评价数据上选择AIVAT启发式可能导致的统计问题；[AV-AIVAT](https://arxiv.org/abs/2608.06362)研究结合置信序列的停止规则。这些是预印本研究方向，不构成本项目可以直接获得某个倍数提速的依据。第一版采用预先固定的评测预算更容易审计。

合作式SMAC与单人Procgen的任务目标和本项目不同，可迁移的是闭环需求、泛化划分和统计方法，不能直接搬用其得分标准。棋类的精确规则与轮流动作也不同于实时同时行动；搜索对比必须额外考虑对手建模与执行时间。

历史搜索63%来自第一阶段指定对手混合与100场景；它不是官方胜率。现有文档还保留历史play bias选择来源不完整的限制，因此应把旧模型作为固定历史基线，新模型的所有阈值只由训练和验证数据确定。

建议将当前论文定位分为三种可选择的主线：平台与benchmark；可信历史观察和信念驱动决策；短期世界模型提高真实交互效率。优先选择能形成完整对照证据的一条，其他能力作为配套模块。

## 第一版 Benchmark 的任务契约

### 游戏范围

第一版固定1v1、明确的客户端与资源指纹、卡牌数值、等级、塔类型和终局规则。先纳入经过部署及机制验证的卡组，逐步扩展普通兵种、建筑和法术。进化、英雄技能、特殊塔兵等另建扩展集，避免未经核实的交互影响主结论。

卡组选择应覆盖快攻循环、坦克推进、空中进攻、诱饵、桥头压力、防守反击、攻城等不同结构；最终名单以该版本支持情况为准。这些是覆盖维度，不是要求采用当前赛季热门卡组。跨版本比较时锁定两个版本的真实差异，任意修改数值只能称为参数扰动。

明确双方是否提前知道对方完整卡组。可以设置“已知卡组但手牌与圣水隐藏”和“卡组需从出牌中发现”两个任务；不能在同一主表混用。固定卡组实验即使没有显式提供敌方牌表，也可能让模型从训练中记住它，须据此限定部分可观察性的主张。

### 观察轨道和执行时钟

| 观察轨道 | 输入 | 评价用途 |
| --- | --- | --- |
| Public Structured | 经规则和可见性审核的玩家公开信息、本人手牌与圣水、允许的历史 | 决策方法主轨道，隔离感知影响 |
| Pixel | 客户端实际可获取画面与相同权限的操作反馈 | 视觉感知到执行的端到端系统 |
| Oracle Reference | 原生全状态或额外隐藏信息 | 特权教师及参考比较，报告信息差；有限模型不保证是理论上界 |

三条观察轨道与下面两种时钟正交组合。

1. 固定模拟时间步：所有方法每0.5秒模拟时间有一次相同决策机会，适合比较策略质量。若推理期间环境暂停，明确标注暂停。
2. 持续推进的实时模式：推理、传输和排队期间环境及对手继续行动，评价真实部署效果。

0.5秒继承项目当前节拍，属于工程选择，不等于人类反应时间。再测0.25、0.5、1.0秒或能力允许的节拍敏感性。超过时限的动作采用预先规定的丢弃或队列规则，不允许因模型不同而暂停对手。

结构观察即使只包含公开量，也可能比人眼读取更精确；因此“无隐藏信息泄漏”与“完全相同的人类感知难度”是两件需要分别说明的事。

## 环境和信息可信性评价

环境测试分成校准集和冻结验证集；同一参考录像不能同时用于修引擎并宣称独立验证。引擎验证与策略训练也有各自的数据切分。

| 层次 | 内容 | 指标与解释 |
| --- | --- | --- |
| 机制 | 移动、攻击间隔、索敌、射程、碰撞、部署、法术、塔激活、轮转、经济、终局 | 按机制族报告通过数/总数及误差，未支持与未测分开 |
| 轨迹 | 给定初始化与动作，比较位置、HP、生成/死亡、塔伤与事件时间 | 短期及完整轨迹误差、首次分歧时间；同胜者只是一个维度 |
| 确定性 | 相同指纹与输入，独立reset或重启重演 | 语义轨迹hash与首次差异；重复一致不能证明规则正确 |
| 对称性 | 交换玩家、视角与相应坐标 | 座位差异及其区间；对真实规则中的不对称作解释 |
| 操作 | 所有支持牌、位置、费用、技能和过期观察 | 提交到消费、拒绝、重复执行、unknown的完整分母 |

单独审计观察字段、mask、搜索器、记忆和模型辅助输入。对相同公开历史及相同actor RNG，扰动未公开的对手手牌、精确圣水、未来命令等，actor输入与预测分布应不变。隐藏状态的替换要与该公开历史相容；该测试检验信息隔离，并不验证所有可能的游戏状态。

合法mask本身也是信息通道：只能使用当前轨道允许的规则和已知量。像素轨道不能无说明地使用原生精确状态修正mask。私有字段、来源ID、文件路径、跨局实体ID和质量标签均不能成为actor的捷径。

公开回放重建、原生自采和独立客户端画面测量应保留不同来源等级。一个环境产生标签再由自己核对标签，证明的是内部一致性。

## 评测套件与核心指标

| 套件 | 主要问题 | 核心输出 |
| --- | --- | --- |
| Environment | 测试条件是否可信 | 机制覆盖、独立轨迹误差、确定性、观察隔离 |
| Tactical | 能否解决明确的局部决策 | 任务成功率、损失、消耗、实际延迟 |
| Offline | 能否在留出历史上学习时机、卡牌和位置 | 事件PR/F1、条件与联合指标、校准 |
| Closed Loop | 自己改变状态后是否仍能获胜 | 固定对手池的宏平均得分、配对差值、逐项表现 |
| Generalization | 结果能迁移到哪些新条件 | 各泛化轴得分与退化量 |
| Systems | 实际部署是否稳定且及时 | 完成率、执行确认、失败、p95/p99时延和资源 |
| Prediction，可选 | 世界和对手预测能否辅助行动 | 多步误差、概率评分、动作排序和闭环收益 |

主评价使用实际游戏结果。令单局得分为胜1、平0.5、负0。每个预先定义的任务层内求均值，再用冻结权重汇总：

\[
S(\pi)=\sum_{k=1}^{K}w_k\,\mathbb E[Y\mid\pi,\mathcal T_k],\qquad \sum_kw_k=1.
\]

第一版建议对卡组对阵和对手类别做宏平均。另报W/D/L和原始胜率，避免把含平局的得分率称为纯胜率。若用真实玩家卡组频率加权，冻结版本、时间窗口和频率来源，并作为第二种部署分布结果。

不要把胜率、预测误差、延迟等任意加权成“综合智能分”。用明确的主指标和辅助结果回答不同问题。最差分组或最低10%分组可以揭示弱点，但应给出每组样本量，避免用极小格子的最低值制造结论。

## 战术任务设计

建议先建立10类任务，每类20个独立前缀，共200个初始任务，分开发/验证/密封测试版本。数量是起步设计，正式精度仍取决于任务相关性和所需效应大小。每类同时有容易、中等和边界实例，阈值由开发与验证集确定。

| 任务 | 变化因素 | 可客观测量的成功条件 |
| --- | --- | --- |
| 进攻单位防守 | 对手单位、距离、可用牌、资源 | 固定窗口内塔伤、额外消耗与存活状态 |
| 拉扯与建筑摆位 | 进入方向、建筑位置、部署时间 | 是否改变目标、塔伤和防守后收益 |
| 对空 | 空中组合、己方对空牌是否在手 | 空军到塔前的处理效果 |
| 法术时机与范围 | 密度、位置、单位移动与HP | 命中效果、净伤害、后续防守损失 |
| 分路与应对 | 两路威胁强弱、资源紧张程度 | 两路总损失及后续局面 |
| 反制牌轮转 | 当前画面相近、此前出牌历史不同 | 是否识别窗口，执行后对战结果 |
| 资源估计 | 不同公开消费历史、相似当前场面 | 估计区间与受约束的进攻/防守收益 |
| 反击转换 | 防守后残兵与对方资源 | 固定后续窗口的推进和受伤 |
| 终盘 | 塔血、剩余时间、轮转、伤害范围 | 实际终局胜负，避免仅奖励伤害 |
| 执行边界 | 卡槽暂空、3张手牌、不可支付、过期mask | 有效动作、正确反馈及后续恢复 |

一题可以有多种好动作。专家标签可用于审查和建立可接受动作集合，不能把“不复刻专家唯一落点”直接判错。能枚举的小任务才讨论精确最优；其他任务的最佳搜索结果称参考解，regret也应称“相对参考解的差距”。

如果没有snapshot/fork，就用fresh reset加相同输入前缀重演，核对到达状态后再分支。带记忆代理还要读取其可见历史来恢复内部状态。对手在分支后按预定公开策略响应，不能继续读取原录像的未来命令并把它当作对新动作的真实应对。记录每个分支的恢复与推理成本。

## 离线学习评价

普通帧准确率会被WAIT比例主导。必须报告全WAIT、简单出牌频率、合法随机与固定时间脚本等参照。

| 对象 | 建议指标 | 必须保留的口径 |
| --- | --- | --- |
| 出牌时机 | 事件precision/recall/F1，PR曲线，时差分布 | 固定容差、一对一匹配；0.25/0.5/1秒可作预声明敏感性分析 |
| 选牌 | 在时间匹配事件上的卡牌准确率、各牌召回 | 同时报时间与卡牌都匹配的联合PR/F1，不能只看成功匹配子集 |
| 落点 | 卡牌条件下距离、分位数、区域成功率 | native坐标/tile/像素单位统一；另报时机+卡牌+位置联合成功 |
| 等待或hazard | NLL、Brier、校准、事件PR | WAIT是区间内没有记录出牌，未必是明确人类意图 |
| 记忆 | 去历史、截断历史、正确历史比较 | 用相同当前观察控制；乱序历史只是辅助压力测试 |
| 数据覆盖 | 每牌、每卡组、每来源、每局动作数 | 行数、整局数与实际确认出牌数分别报告 |

事件匹配要冻结细则，避免在大量近邻事件中按模型是否猜中卡牌来挑选有利匹配。项目现有时间匹配可作为一个指标，另增加明确的联合匹配定义。

评价推理路径必须与部署一致，包括mask、温度、argmax/采样、play bias、坐标变换和fallback。超参数与checkpoint只在验证集选择。Decision Transformer等方法若使用目标return，部署时按验证确定的目标输入，不能输入测试局的真实未来回报。未来动作可以作为监督标签，不能进入当前观察或未来信息派生的actor特征。

离线复制人类动作的能力和实际胜率是相关但不同的问题；有多种合理动作时，交叉熵也不等于策略价值。离线结果用于定位问题和筛选候选，最终由闭环评价策略。

## 记忆和对手建模的评价

敌方手牌、轮转和圣水监督可在研究环境中由oracle产生，但只用于训练目标或单独诊断。部署预测只依赖合法公开历史，测试集中也保持同一约束。

| 预测对象 | 基线 | 指标 |
| --- | --- | --- |
| 敌方可能在手的牌 | 频率先验、按公开轮转更新的规则belief | 逐牌概率Brier/NLL、覆盖率、校准 |
| 敌方圣水 | 已知消耗与恢复的区间规则 | MAE、区间覆盖率与区间宽度 |
| 下一次敌方动作 | 无条件牌频率、规则belief | 卡牌/类别NLL、时机hazard及分组表现 |

需要两类证据：预测是否改善；改善是否帮助决策。辅助头与无辅助头使用相同actor输入、相近参数及训练预算，并在未见对手整局上比较。辅助头仅训练时增加oracle监督的实验，要与纯公开监督实验分开。

专门设计“当前公共画面相近、过去轮转不同”的成对题。先验证题目确实会改变合适行动，而不是凭设想命名“记忆题”。若固定时间脚本表现接近带历史代理，就应修订任务或收窄记忆的贡献主张。

## 世界模型的评价

预测优先采用有决策意义的量：实体存在/生成/死亡、位置、HP、塔伤、公开资源、奖励和终止。对象集合先按明确规则匹配，不能按数组下标计算误差；缺失和未知量保留mask。

1. 先评价0.5、1、2秒，再根据验证结果扩展3、5秒。
2. 与保持状态、线性移动、简单规则外推比较，避免静态或多数不变对象让模型轻易得高分。
3. 分开报告每步接收真实新观察的一步预测，与不接收真实未来观察的多步open-loop预测。
4. 条件于已记录双方动作的离线预测可以作为动力学诊断，但它使用的是评价条件；部署规划时的未来敌方动作必须由公开信息预测或采样。
5. 用可重置前缀构造少量候选动作分支，比较预测的动作排序、成对偏好与实际效果。
6. 最后比较相同真实数据和计算预算下，加入模型是否改善真实闭环得分或达到同等得分所需的真实交互量。

“同一条历史轨迹预测准确”不证明对未执行动作的反事实预测也准确。像素MSE或视频质量也不能替代动作价值排序。先冻结验证门槛再进行想象训练，不能看测试结果后决定哪些预测量算重要。

如果主张省样本，同时公开真实对局/模拟秒数、示范数据、特权教师查询、模型生成步数与总墙钟成本。把真实交互换成昂贵oracle查询并不自动意味着整体更高效。

## 对手池与交叉对战

第一版建议维护四种互补对手：调试参照、固定锚点、训练池和密封挑战池。

| 对手组 | 示例 | 用途 |
| --- | --- | --- |
| 调试参照 | 全WAIT、合法随机、固定时机脚本 | 发现出牌失败与benchmark捷径，不占主榜大量权重 |
| 固定锚点 | 规则快攻、规则防守、固定学习checkpoint、公开信息搜索 | 各次实验可比的主评价分布 |
| 训练池 | 自博弈当前/历史策略、用于课程的规则策略 | 学习多样性；不能自动成为未见测试对手 |
| 密封挑战池 | 不同实现或留出的风格、独立训练的对手、专门攻击者 | 检验过拟合与抗针对能力 |

把同一训练池checkpoint换个名字或RNG，不算新的策略类型。对手规则、模型hash、mask、搜索预算和版本都冻结。随机对手的出牌节奏需要合理定义，不能因大量非法或无意义请求让它过弱。

主表报告固定锚点池的宏平均；另提供学习代理、关键基线的两两对战矩阵，每格标局数。Elo/TrueSkill只作为当前池、卡组分布及版本内的辅助标度；更换对手池要重校准，不能映射为官方杯数。

遇到A克B、B克C、C克A，保留矩阵和分组表现。α-Rank或有限策略集的经验博弈分析可以补充，但没有消除未纳入策略带来的盲区。

抗针对实验：冻结每个被测代理，为其分配相同的攻击者训练预算；攻击者在独立验证配置中选择，然后在新的共同测试配置中评价。报告最强已发现攻击者的得分或被测代理的退化。该值是经验漏洞探测；受有限攻击者能力和抽样误差限制，不能称精确exploitability或纳什保证。

## 数据划分与泛化矩阵

先分整局或更高层泄漏组，再做切片、重建、增强和滑窗。同一对局的双方视角、重采、镜像、不同初始化假设和近重复必须同组。相同来源但无可靠battle ID的样本，采用可解释的近重复匹配并保留未知风险。

| 测试划分 | 留出什么 | 可支持的泛化表述 |
| --- | --- | --- |
| ID配置 | 同分布的新整局与起手 | 同一任务分布的新对局 |
| 起手 | 新的合法卡序、非固定开局 | 对初始条件变化的稳健性 |
| 卡组组合 | 牌都见过，八卡组合未见 | 组合泛化 |
| 对手策略 | 新实现或独立留出的策略族 | 对手风格泛化 |
| 玩家 | 未见的人类玩家及其整局 | 跨玩家行为泛化 |
| 数据来源 | 留出一种采集/标注来源 | 在语义可对齐前提下的来源迁移 |
| 时间或补丁 | 后续时间段或真实另一版本 | 时序/版本迁移，零样本和少量适应分开 |
| 卡牌 | 训练未见的新牌及相应参数接口 | 新卡泛化，需要单独的表示与协议支持 |

不要把“新卡组”默认等同“新卡牌”。先测单个变化轴，再测试未见卡组×未见对手的组合变化，才能解释失败来源。各来源的坐标、时间、标签强度和可用字段未对齐时，不强行拼成共同测试集。

用历史公开数据时，按时间拆分可以降低未来信息穿越，但引擎补丁、数值与玩家习惯同时变化时仍存在混杂，需要单列。所有筛选条件在查看模型测试成绩前冻结；发布筛选前后分母及排除原因，避免只留下容易重建的对局。

## 基线与消融设计

### 有解释力的基线

建议包含：合法随机、固定时间脚本、公开规则策略、单帧BC、带历史BC、合理训练的masked PPO/自博弈、公开belief加搜索。若主张从示范中学习更高效，加入BC加RL；若主张时序建模优越，加入相近容量的RNN与Transformer。Oracle搜索与特权监督方法单列。

第一阶段PPO只训练很短、argmax几乎不出牌的历史模型可以作为故障案例，不能充当“已经击败强RL基线”的主要证据。基线要使用合理的训练预算、公开调参空间和一致的部署路径；训练不稳定也应报告，而不是删除失败seed。

不能直接把其他论文在不同版本、不同引擎和不同卡组上的胜率放进本项目主比较。能在共同契约中适配的方法标为重新实现；协议不兼容的工作在相关研究中比较，明确差异。

### 结合第三阶段的消融

| 实验 | 唯一主要变化 | 要回答的问题 |
| --- | --- | --- |
| A到B | 修正缺失、mask、可信字段与观察语义 | 数据与输入契约带来多少收益 |
| B到C | 单帧到历史记忆 | 历史是否改善判断与整局结果 |
| C到D | 共享落点到按卡牌条件化落点 | 动作结构是否有帮助 |
| D到E | 加入辅助预测 | 预测监督是否帮助部署策略 |
| 对手头 | 无头、规则belief、学习预测 | 收益是否出现在未见对手 |
| 世界模型 | 无模型、简单外推、学习模型 | 是否提高动作排序和闭环表现 |
| 想象训练 | 相同真实数据下有无想象 | 整体收益是否超过新增成本 |
| 可变时机 | 固定步长与hazard/事件调度 | 出牌时机与实时预算的权衡 |
| 外部数据 | 相同模型下增减指定来源 | 来源贡献与标注偏差 |

A到B同时改变数据表示时，不能归因为网络算法。对核心论文结论进一步建立“基础观察/可信观察×单帧/带记忆”的2×2实验；在所有方法共同可用的输入条件下测记忆效应，并分析交互。控制参数量或增加容量匹配的无记忆网络，避免把模型更大当成历史推理有效。

所有主要消融共用版本、数据切分、支持卡、动作空间、节拍、对手、后处理和评测配置。搜索比较既报告固定展开数结果，也报告相同墙钟预算下的实际效果。训练成本与部署成本分别核算，评测额外调用模拟器的次数也计入。

## 统计分析与样本量

### 配对与独立性

模型A与B使用相同的卡组对阵、初始化、对手checkpoint及其RNG、座位和时限。双方同时从决策前观察行动，避免顺序调用让后行动者看见同一tick对方新动作。换边时卡组和起手随逻辑玩家交换，并变换视角。

每个底层配置的两个座位组成一组；先平均该组两个座位，再计算A与B的配对得分差。区间重采样保留两种方法与两个座位的配对关系。固定对手与共同RNG可减少无关差异，但策略改变后的轨迹通常会分歧，不能声称后续随机事件全部相同。

训练随机性和评测随机性分开。建议主要学习方法至少3个独立训练运行，目标5到10个；这些数量是资源折中，不是统计充分性的保证。独立运行从初始化/数据顺序等重新开始，不能把同一checkpoint续训算作新seed。

对一个冻结checkpoint的配置泛化区间，可按对阵层分层、按换边配置组bootstrap。对算法平均表现还要纳入独立训练运行；相同测试配置跨方法共同重采样。训练运行可以分别重采样，只有实际设计为配对的训练运行才按训练块配对；数字相同的seed本身不保证合理配对。若同一个训练模型跨多个任务复用，其任务间相关性也要保留。

只有3个训练运行时，bootstrap对训练总体的不确定性可能很不稳定，应同时展示各运行原始点和范围，收窄强度主张。更多测试对局只能减少该checkpoint的对局噪声，不能补偿训练运行不足。

固定卡组集合内的结论与对更大卡组总体的推断不同。前者保留各层权重，后者还需要合理的卡组抽样方案；没有抽样基础时，不把有限手选卡组自动推广到所有卡组。

### 局数的直观尺度

在独立二项结果且胜率约50%的简化假设下，95%正态近似半宽为1.96√(0.25/n)。下表只是精度估算，不是功效分析，也没有考虑换边、共享卡组与训练seed的相关性。

| 独立局数n | 近似半宽 |
| --- | --- |
| 100 | ±9.8个百分点 |
| 400 | ±4.9个百分点 |
| 1000 | ±3.1个百分点 |
| 2500 | ±2.0个百分点 |

实际报告二项胜率可使用Wilson区间，配对比较使用相应分组统计。两种模型各自区间是否重叠不能替代它们差值的检验。小于5个百分点的目标提升，通常需要比演示更大的独立样本及更仔细的设计；用pilot估计配对差值的方差，再按预声明的效应、显著性水平和检验功效规划数量。

预先指定一个主要比较与主要指标，关键次要比较用Holm等方法处理多重比较。探索性分析标记为探索性。禁止不断查看普通95%区间，并在恰好显著时结束；如需顺序停止，另行设计适当置信序列或组序贯规则。

### 失败与缺失

冻结计划局数后，保留每次attempt。代理崩溃、解析失败或持续超时，按预先规定的系统比赛规则判负或由fallback继续；这些是系统表现。独立于代理的基础设施故障采用有次数上限的共同重跑规则，保留全部失败attempt；无法完成时同时报告完成率、条件得分和缺失结果的上下界，不删除后补到满意胜率。

真实游戏终止、人工截断、墙钟超时、基础设施中断分别标记。unknown不是draw；推断提交不是执行成功；环境拒绝和策略主动WAIT分开。只在成功完成局上计算的胜率必须标为条件胜率。

## 运行可靠性与实时性

逐次记录观察产生、决策开始/结束、请求发送、引擎确认执行及反馈返回的时间和tick。端到端反应延迟采用事件或有效观察到实际执行之间的间隔；神经网络forward延迟单列。p50、p95、p99均报告，另给deadline miss与最严重长尾。

| 指标 | 建议口径 |
| --- | --- |
| 对局完成率 | 自然终局数/计划局数，同时列失败类别 |
| 命令消费确认率 | 唯一确认消费的非WAIT命令/提交的非WAIT命令 |
| 拒绝与unknown | 各自除以同一非WAIT提交分母，重复提交另列 |
| 出牌退化 | 长期不出牌、轮转锁死、fallback使用率及阈值 |
| 资源 | 训练与部署CPU/GPU时间、内存、模型大小、原生调用次数 |
| 数据效率 | 独立整局、实际出牌、环境模拟秒数、决策数及示范/教师量 |
| 复现成本 | 新进程加载、reset、prefix重建与整局墙钟时间 |

漏圣水、无效塔伤等行为可作诊断，避免直接定成主奖励：等待可能是正确决策，消耗少也可能只是没有行动。失败案例按预先分类从全部失败中抽样，同时展示成功和中位表现回放，避免只展示高光。

## 分阶段实验预算建议

先实测单局含reset、推理、日志的墙钟时间，再用“总局数×实测平均耗时÷可稳定运行的实例数”估算预算，并预留恢复成本。目前原生单owner约束下实例数为1；不能直接按CPU核心数并行。

| 阶段 | 建议规模 | 可以回答的问题 |
| --- | --- | --- |
| 契约与smoke | 当前支持子集，各候选10到20局，加部署边界夹具 | 能否执行与保存证据 |
| 数据可用性 | 延续50独立整局、2000确认出牌里程碑，各split保留整局 | 能否训练与诊断；通常不支持细粒度论文强度结论 |
| 开发pilot | 4己方卡组×4敌方卡组×3对手×2座位=96局/checkpoint | 估算耗时、差值方差，发现捷径与失败 |
| 资源受限正式比较 | 预先平衡的256个换边配置组=512局/checkpoint；关键方法3个以上独立训练运行 | 对声明范围内主要差值作初步严谨比较，精度由实际区间决定 |
| 较完整主测试 | 8己方卡组×8敌方卡组×4锚点对手×2起手×2座位=1024局/checkpoint | 较广覆盖的固定分布结果 |
| 泛化扩展 | 从新卡组、新对手和联合变化分别抽取独立配置组 | 对指定变化轴的迁移能力 |

512局预算的配置组按卡组对阵×对手层平衡抽取，名单在评测前冻结。若5种方法各5个训练运行全部做1024局，就是25,600局，尚未计入对手矩阵和泛化；应先用开发数据筛选，再把正式预算集中于核心比较，最终密封测试中仍报告所有预先选定运行。

两两矩阵也有成本：8个冻结代理，每对100局且100局已含换边，共28×100=2800局。该矩阵解释这些代理的克制关系；如果每种方法仅取一个代表checkpoint，不能把矩阵当成已覆盖训练随机性的算法排名。

原生预算确实不够时，可在近似环境完成较大规模的方法探索，原生环境做关键对照验证；两套结果分表，最终结论注明迁移范围。只完成50或100局时保留初步结论，不能用反复重演同一配置凑独立样本量。

## 可支撑论文的实验组织

建议围绕四个问题组织正文：环境是否能公平复现；方法是否改善整局；提升来自哪里；哪些变化下仍然有效。训练算法、视觉和世界模型无需全部成为主要贡献。

真人验证作为独立实验：预先定义经验层次和招募标准，固定版本、等级、卡组与观察/反应约束，提供练习，随机化顺序，按玩家分组统计。每名玩家多打几局不是增加同样数量的独立玩家；历史杯数不跨版本直接可比。先做可复现本地人机测试，也能支持限定范围内的人类比较。

如果方法只在熟悉对手上提高，结果应写成分布内收益；如果记忆预测更准但整局无增益，这是辅助任务未转化为控制价值；如果世界模型带来的收益小于计算成本，保留该权衡。可信的失败分析也能构成研究结论。

## 建议交付的 Benchmark 产物

建议复用现有evaluation、versioning、observability、trajectories和质量审计模块，增加统一协议和统计汇总层，不在此次调研中启动另一套游戏引擎或控制器。

每一版benchmark至少交付：

1. 环境、观察、动作、时序、计分与失败规则说明。
2. 冻结的训练/验证/测试分组，近重复规则及筛选分母。
3. 对手及模型hash、卡组和配置清单；密封测试按受控方式保留。
4. 同一推理路径的离线与部署一致性证据。
5. 逐局与逐命令原始记录、配对组ID及结果汇总代码。
6. 训练运行与选择记录、计算成本、学习曲线和完整失败记录。

## 优先实施顺序

第一步，固定一组可完整操作的八卡组，打通每种兵种、建筑、法术的合法部署与实际消费证据，并修正公平战场观察。完整操作不要求第一版覆盖全部卡牌，但每个主测试卡组必须覆盖。

第二步，冻结公开结构观察主轨道、0.5秒节拍、对手池和计划局清单；把旧模型留作历史基线，重新收集符合共同契约的训练与验证数据。

第三步，建设200题量级的战术任务和96局/checkpoint的开发pilot，检验固定时间脚本、无历史和全WAIT等基线，测量实际预算与配对方差。

第四步，运行可信观察与记忆的核心对照，在多个独立训练运行和新的密封配置上做正式整局比较，再扩展卡组和对手泛化。

第五步，仅在预测与排序验证有价值时，把对手头、世界模型或想象训练加入主贡献；视觉端到端和真人实验根据论文主张补充。研究主线应随可重复的证据收敛。

## 建议精读顺序

最优先读Oracle Planner的实验与表III、VI，SEAT的环境与实验设定，以及KataCR第5节和表3，用来理解直接相关工作的比较边界。接着读Statistical Precipice、SMACv2、α-Rank，再读AlphaStar与OpenAI Five的评价部分。需要视觉或LLM路线时读VideoGameBench、lmgame-Bench与TowerMind；需要昂贵评测降方差时再读AIVAT及2026年的后续工作。

这些文献共同提供的设计原则是：先明确评价对象与实验条件，再以独立结果验证方法，用分解任务解释机制，并把有限样本与任务覆盖造成的不确定性留在结论中。
