# 因果时序模仿：何时行动、选择什么、落在哪里

本实现位于 `timing.py`、`timing_training.py`，复用原有公开实体／空间／GRU 编码器，保留 `imitation-v1.pt` 和 `imitation-full-v2.pt` 的格式与加载能力。它解决时序标签、目标分解、部署解码和独立验收之间的契约；模型是否有用以独立整局和实际执行结果判定。

## 为什么旧联合分类容易一直等待

旧模型将 WAIT、四个手牌槽与能力按钮放进同一个 softmax。即使所有非 WAIT 动作的总概率为 0.6，如果这 0.6 被四张不同的牌均分，每张只有 0.15，联合 argmax 仍选择概率 0.4 的 WAIT。给出牌标签加权并不能直接消除这个决策语义。原来把半秒窗口内后续动作贴到窗口开头状态，还可能要求模型在尚未看见对方新动作时预知教师反应。

现在训练三个条件目标，分别按自己的有效样本数量归一化：

1. 事件头：在当下观察和过去历史下，教师是否在这个控制时刻请求非 WAIT 动作。
2. 条件选牌头：只在真实非 WAIT 事件上学习手牌槽／能力按钮。
3. 条件位置头：只在有确认执行和有效位置的普通部署上学习该牌的网格分布。

事件损失保留自然时间分布，不抽掉等待帧，不复制出牌帧改变 GRU 时间。没有非 WAIT 合法动作时，事件概率严格为零。当前没有能力正例的数据不能证明能力策略学会了。

## 时间与执行契约

每条数值轨迹除原有公开观察、动作、mask、`ticks` 外，必须包含下表。全部由同一次实际采集产生；请求与执行属于审计标签，不能作为当前 actor 输入。

| 字段 | 约定 |
| --- | --- |
| `observation_tick` | 动作请求前观察的引擎 tick，与 `ticks` 相等 |
| `request_tick` | 真实非 WAIT 标签必须与观察 tick 相等；WAIT 为 -1 |
| `confirmed_tick` | 引擎确认实际执行的 tick，不能早于请求；WAIT 为 -1 |
| `elapsed_ticks` | 当前与上次观察实际相差的 tick；每局首帧为 0 |
| `decision_ticks` | 当前计划的控制窗口，固定版本主实验为 10 tick，即 0.5 秒 |

迟于观察的未来请求不能标注为当前动作；缺少执行确认也不能计作已确认出牌。当前训练器拒绝执行延迟超过一个控制窗口的数据，这类数据应先用显式 pending-action／动作确认状态机处理。不能把延迟很大的执行硬移回请求 tick。

事件头输出非负风险率 `lambda`，声明窗口 `dt` 内概率为 `q = 1 - exp(-lambda * dt)`。实际经过时间另经编码器进入 GRU；改变未来窗口不直接改变过去隐状态。单调校准作用在风险率上，保留相邻窗口生存概率的数学组合关系。**这一数学性质不是改变控制频率后仍准确的实验证明**：本轮训练与正式部署均为固定 0.5 秒，其他频率还需同节拍数据与闭环验收。

在线首帧默认经过时间为 0，之后固定节拍调用默认 10 tick；显式传入的 `elapsed_ticks` 优先。真实设备调用必须提供实际耗时，不能把变动延迟伪装成固定间隔。

## 独立选择、校准与验收

本轮数据由新种子整局采集；旧高手重建的两批已查看测试集均不参与。默认 60 个训练局中按固定哈希留 6 局作 monitor，余下 54 局训练；10 个 validation 局分成 5 个校准／阈值拟合局和 5 个冻结检查局；10 个 test 局只在模型和全部解码参数冻结后读取预测结果。双方视角始终归属同一整局分组。

模型轮次由 monitor 的事件 NLL、真实事件条件选牌 NLL、真实牌条件位置 NLL 之和选择。校准只使用 validation-fit，拟合两个单调风险率参数。确定性事件阈值最小化可行动帧的 `0.5 * FPR + 0.5 * FNR`，并列取更高阈值。结果同时报告自然时间和可行动时间的 NLL、Brier、Average Precision，以及常数训练先验基线。阈值达到平衡错误率 0.5 或仅仅开始出牌，都不能算学会时机。

严格同 tick 事件 precision／recall 为主指标；另预先固定 ±10 tick 的一对一事件匹配，禁止多次预测匹配同一个真实动作或事后扩大容差。选牌正确率、条件位置距离、完整动作精确率分别列出，不能用事件 recall 代替正确作战。

同数据 `--model-kind joint` 基线使用相同整局训练／monitor 分组、相同编码器大小与优化预算，保留旧联合加权 CE 和联合 argmax；用于区分同版本数据上的新旧训练方式。它与新方法的差异包含目标分解、显式时间和事件校准，不能把整体差异全部归因于某一个部件。

`timing_comparison.py` 校验两臂确实遵守测试前冻结的计划，并逐项比较测试动作、时间与轨迹 ID。它还把位置、可行动 mask 和每条预测的整局归属直接绑定到原始 NPZ，核验测试前冻结文件中的模型 SHA、数据 SHA、测试局 ID 和时间容差；两份预测彼此一致仍不足以通过来源审计。差值区间按原始整局 bootstrap，两方视角始终同时抽样，不能把同局的每一帧或两个视角当成独立对局增大样本量。只有 10 个测试局时，区间仍可能很宽。

```bash
.venv-cloud/bin/python -m arena_lab.timing_training \
  --index outputs/arena-next-20261113/data-paired-v1/index.json \
  --output outputs/arena-next-20261113/timing-v1 --epochs 12 --threads 2

.venv-cloud/bin/python -m arena_lab.timing_training \
  --index outputs/arena-next-20261113/data-paired-v1/index.json \
  --output outputs/arena-next-20261113/timing-joint-baseline-v1 \
  --model-kind joint --epochs 12 --threads 2

.venv-cloud/bin/python -m arena_lab.timing_comparison \
  --plan outputs/arena-next-20261113/timing-experiment-plan.json \
  --candidate outputs/arena-next-20261113/timing-v1 \
  --reference outputs/arena-next-20261113/timing-joint-baseline-v1 \
  --output outputs/arena-next-20261113/timing-comparison-v1.json
```

每轮保存实际训练吞吐、monitor 指标、已完成优化步、模型和优化器／RNG 恢复状态。新运行拒绝覆盖已有目录。`--stop-after-epoch 1` 可在不触碰 test 的情况下保留第一轮状态；使用原命令加 `--resume` 从该轮继续，配置与数据 SHA 必须一致。已完成的运行拒绝恢复，防止借恢复入口重复读取测试集。

`selected.pt` 为 monitor 选出的校准前模型；`best.pt` 为全部参数冻结后的最终模型。`frozen-before-test.json` 先写出模型 SHA、解码参数、数据 SHA、测试整局 ID 和时间容差，再进行测试。`report.json` 包含各分组指标，`*-predictions.npz` 保留数值预测供独立核对。结果目录中的 `resume.pt` 是研究恢复工件，不应充当部署权重。

```bash
.venv-cloud/bin/python -m unittest tests_cloud.test_arena_timing -v
```

测试包含联合 MAP 的 WAIT 回归、时间组合规律、首帧／整序列／在线一致性、未来标签拒绝、全部 WAIT mask 的有限梯度、动作概率与精确熵一致、保存字节可重复，以及实际中断后恢复与不中断训练的逐权重完全相等。测试夹具不是人类高手数据，也不计入战力验收。

## 接入自博弈与设备

`model.load_policy` 自动识别旧模型与时序模型。`PolicyAgent` 继续负责每局重置 GRU。确定性推理先判事件，再选条件牌槽和位置；随机推理使用同一个完整联合分布。`timing_action_log_prob_entropy` 提供包含 WAIT、技能与卡牌条件位置的精确联合 log-probability 和熵，自博弈更新复用它，不另写一套动作概率。

加载时仍严格校验完整环境身份。评估环境用 checkpoint 保存的 `environment_identity.config` 构建，再通过预先冻结的逐局 reset 参数设置种子、牌组、等级等；不能放宽二进制、卡表、观察结构或时钟身份来让加载勉强成功。

本轮同版本规则教师轨迹能够验收状态和动作对齐，但不是人类高手模仿。真实截图输入还必须经过独立视觉识别、单位跟踪、坐标校准、过期观测拒绝及动作确认。引擎实体轨迹直接喂入模型的结果不算截图策略或真实设备闭环验收。

## 本轮实际时序训练结果

80 个新整局包含 88,828 个有效控制时刻和 11,699 次确认部署；没有能力动作正例。原始整局划分为 60／10／10，训练器再按上文固定规则分出 monitor、calibration 和 validation-check。数据索引 SHA256 为 `641bece650374eb5401d35b4b8130bab6610ab8f525f270236450d9e8054e5d1`，双臂冻结计划为 `outputs/arena-next-20261113/timing-experiment-plan.json`。

新模型已完成预定 12 轮、共 5,979 次优化更新，由训练 monitor 选择第 11 轮的 5,475 次更新模型。容器重建中断了第 7 轮后的运行，使用原配置和检查点恢复；原日志和恢复日志分别保留在 `timing-logs/timing-v1.log` 与 `timing-logs/timing-v1-resume.log`。恢复前后冻结的三份训练源码 SHA 均一致，没有根据测试结果更改预算。12 轮纯训练合计 974.53 秒，整体约 741.36 个有效标签／秒；恢复后的五轮为 921.73–1,048.11 标签／秒。包含 monitor、校准和最终测试的已记录运行时间为 1,087.87 秒，不含初始数据审计和中断停机时间。

最终风险率温度为 1.00665、log-scale 为 0.15283，事件阈值为 0.232777，均由 5 个 calibration 局拟合后冻结。模型保存在 `outputs/arena-next-20261113/timing-v1/best.pt`，SHA256 为 `b368ec2aa4d22f463fe211ea9239530317a3daf1f31b1a83ec8389dcc4eef51b`。测试只有 10 个独立整局、20 个视角、10,840 个控制时刻和 1,425 次真实部署；以下均为第一次冻结测试结果。

| 指标 | 时序模型 | 同一权重移除战场实体 |
| --- | ---: | ---: |
| 严格同 tick 事件 precision | 69.98% | 25.21% |
| 严格同 tick 事件 recall | 86.39% | 76.42% |
| 真实事件条件下选牌正确率 | 88.56% | 74.25% |
| 真实牌条件下落点精确率 | 55.79% | 19.23% |
| 真实牌条件下平均落点误差 | 0.996 格 | 6.214 格 |
| 何时／选牌／位置全部正确 | 40.21% | 11.93% |
| 可行动时间事件 NLL | 0.2257 | 0.7348 |
| 可行动时间事件 AP | 0.8681 | 0.2778 |

同一测试上的常数训练先验 NLL 为 0.5332；模型在可行动时间的事件识别优于该基线。预先固定 ±0.5 秒一对一匹配的 precision／recall 为 70.78%／87.37%，主指标仍使用严格同 tick，不把容差指标替换成主结果。独立 validation-check 的 precision／recall 为 70.85%／86.62%。移除实体是同一权重的输入消融，没有单独重训，说明该模型依赖战场输入，但不能据此推出任意场景的视觉泛化能力。

完整报告、逐帧预测、冻结清单和补充审计位于 `outputs/arena-next-20261113/timing-v1/`。`report.json` 顶层 `calibration` 保存的是校准分组指标；数值校准参数以 `frozen-before-test.json` 的 `calibration` 和 checkpoint metadata 的 `event_calibration` 为准，`audit-summary.json` 用 `calibration_parameters` 显式列出。时序契约 12 项回归测试通过，日志为 `outputs/arena-next-20261113/timing-logs/timing-tests-after-integrity.log`。

另外使用实际训练局的连续 128 帧核对最终权重：整序列计算与逐帧 `PolicyAgent` 的牌槽、落点全部相同，包含 21 次非 WAIT 预测，GRU 隐状态在声明容差内一致，reset 后首动作一致。证据为 `deployment-parity.json`；这是部署接口检查，不是再次评分测试集。

这些结果证明本轮同版本规则教师的事件、选牌和位置可以被学习，不能替代独立闭环胜率或人类高手模仿验收。仅一个训练种子和 10 个测试局也不足以证明稳定的跨种子收益。

## 同数据 joint 基线与负结果

joint 基线按测试前冻结的计划完整执行 12 轮、5,979 次更新，训练 monitor 选择第 12 轮。它使用相同的 54 个实际训练局、每轮 60,206 个有效标签、相同的随机种子和优化预算。最终模型为 `outputs/arena-next-20261113/timing-joint-baseline-v1/best.pt`，SHA256 为 `2f4fb8ecd6aba2adcd5e708e7e7274805001956bbe0088f99447f125c6e6f2d8`。纯训练 667.77 秒、平均 1,081.92 标签／秒，记录的训练与评估总时间 744.45 秒；候选早期运行经历了不同的资源占用和中断，不能用两个总耗时直接归因模型结构的速度差。

下表差值均为“时序候选减 joint 基线”。区间使用预先声明的 2,000 次原始整局配对 bootstrap，双方视角同时抽样；这是单种子、10 个测试局的逐项区间，没有将多个指标的区间解释为统一的晋升检验。

| 指标 | 时序候选 | joint 基线 | 差值的 95% 整局区间 |
| --- | ---: | ---: | ---: |
| 严格事件 precision | 69.98% | 76.87% | -9.76 至 -3.97 个百分点 |
| 严格事件 recall | 86.39% | 86.04% | -1.67 至 +3.52 个百分点 |
| 条件选牌正确率 | 88.56% | 88.42% | -1.20 至 +1.27 个百分点 |
| 条件落点精确率 | 55.79% | 59.16% | -5.71 至 -1.08 个百分点 |
| 完整动作精确率 | 40.21% | 43.93% | -5.98 至 -1.13 个百分点 |
| 自然时间事件 NLL，越低越好 | 0.13184 | 0.12938 | -0.00962 至 +0.01400 |

joint 在这批对齐数据上同样能稳定预测非 WAIT。新方法本次没有胜过同数据基线；事件 precision、条件位置和完整动作表现更低，其余主要差值区间跨零。本轮数据实现建立了两臂共用的因果时间契约，新策略另外提供显式风险率和校准接口；这些实现价值不等同于本次策略能力提升。

早期高手重建实验与本轮同时改变了来源质量、版本、对手、训练预算等条件，也不能将跨轮指标差异完全归因为状态对齐。当前可支持的结论是：**这批对齐数据上，两种方法都能学习行动；本轮独立结构对照未显示时序候选收益。**后续应按冻结的闭环晋升规则保留并评估两个权重，优先检查真实作战中的误行动和位置偏差；进一步改变目标、阈值或采样后须使用新的独立验收，不能反复利用这里的 10 个 test 局挑方案。
